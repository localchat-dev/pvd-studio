# 原版容器前缀写出的设计边界

原版 v1 容器写出只有独立实验，尚未接入仓库中的桌面、CLI 或正式导出 API。项目自读和原文件逐字节重建不能替代 PVD3 实际打开、正倒放和重存；正式实现与验收条件见路线图 `FILE-01`、`FILE-02`。

## 前缀范围

受限方案只保留从第 0 帧开始的完整前缀，要求单 Scene 生命周期、唯一 frame section、空 event=0 快照及空原版相机表。任意中段裁剪、多 Scene、非空相机表和其他版本需要独立设计。

写出需重建容器头、通信目录、帧区间、事件页和索引，并重新定位 type-10 保存实例与 backing 数据。帧尾后的分析事件不能移动到最后一帧，未知元数据只能在已确认不需要修改的范围内保留。

## 完整性要求

保存实例应检查固定布局、继承字段、数组、ObjectRef/StringHandle 及 packed 引用，并与该时刻已传输属性比较。普通正向读取跳过的辅助对象体也必须有效；仅用正向自读无法验证全部撤销及快照引用。

必须拒绝无效撤销链、悬空生命周期引用、重复 local ID 和与事件状态不符的保存实例。最终名称与显示目录只代表保存时状态，不能补造缺失的变更历史。

原版读取现有的 512 MiB 文件、64 MiB 元数据及辅助索引预算同样需要在规划阶段约束写出膨胀；内存字节切片实现不能宣称大型文件流式导出。发布需遵循[无覆盖输出](cli-output.md)，包含取消、源变化、部分写入和同步失败。

容器结构依据见[原版文件格式](original-file-format.md)，真实多页和非空起点仍需独立配对输入。
