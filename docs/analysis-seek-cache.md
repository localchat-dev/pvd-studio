# 分析恢复与缓存

历史定位包含目录读取、场景恢复、分析基线加载、事件重放和缓存维护。返回结果应用到 CPU 场景、再进入界面与 GPU，这些阶段分别计时。

## 后端

Resident 使用不可变完成根和分页基线，连续窗口最多保留 120 帧分析根，共用会话 192 MiB 预算域。命中目标根不重放分析事件；窗口外按目录恢复再向前应用。

Legacy 使用共享基线与重放锚，上限 32 条/192 MiB。条目持有可失效的弱租约，不能延长过期历史。近期锚过多时优先淘汰较旧者，同时保留必要段首基线的优先级。

## 准入与恢复

邻近重放锚合并，避免复制大容器后才决定丢弃。原始基线和冷读取回填保留必要恢复点。候选查找范围是策略限制，不是重放耗时上限。

取消或失败不发布游标；换源和跨段恢复释放被替换根。场景撤销、分析根缓存及磁盘滚动是不同机制，详见[共享历史](shared-history.md)。

## 测量

区分捕获基线命中、真正分析缓存未命中与冷读取回填。逻辑冷定位清理应用缓存，不表示操作系统文件缓存也已清理。记录完整结果真值和计时范围，不把 seek 时间换算为窗口帧率。

Legacy 与 Resident 路径的缓存成本应分别测量。整体回归见[历史验收](shared-history-integration.md)，输入要求与已知问题见[验证说明](validation.md)。
