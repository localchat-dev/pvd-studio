# 分析维护与积压

分析事件由接入、窗口维护和不可变状态发布构成。常驻分配或元数据可能长期超过软水位；只按总量反复裁剪会扫描无法淘汰的数据。

## 维护调度

`RetentionSchedule` 根据上次维护后的增长和剩余预算安排压力维护。常规窗口随帧推进，压力窗口保留较短历史；没有维护需求时不生成新的分析修订。

Legacy 的内存分析单独共享，性能更新不复制不变内存状态；Resident 使用共享树与分块序列。旧显示根保持不可变，后端边界见[分页分析](resident-analysis.md)。

## 诊断

`analysis_maintenance` 与 `analysis_ingest` 分别记录维护和接入，后者仍可能包含写时复制。`analysis` 为父阶段，包含二者；不能把父子时间相加或把未计入子阶段前后的 self 时间直接比较。

接收配额与处理能力独立。放宽配额只延后容量边界，不能解决解码慢；磁盘提交、消费通知与取消共用同步谓词，避免丢失唤醒。

## 验证

检查超过软水位的常驻数据、增量维护、快照不变、内存游标、磁盘随机/倒放和完整语义。真实 SDK 生产器与命令见[验收方法](acceptance-plan.md)，接收空间保护见[接收策略](receive-backpressure.md)。

分析维护与实时窗口的回归见[验收方法](acceptance-plan.md)。远端负载、跨机器和持续接收性能需独立验证。
