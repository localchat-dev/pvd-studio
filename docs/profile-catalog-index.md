# 完整 SDK 文件的首次开始时间目录

完整文件的“性能 → 事件曲线 → 排序”提供标识顺序和首次开始时间。默认使用标识顺序；首次开始时间需要 SDK 文件路径和 Windows 派生索引。

首次开始时间按完整 zone/event/thread/context 身份聚合，取完成区间与未结束起点中的最小 tick。只有未匹配结束、没有已知起点的身份排在最后；同一 tick 按完整身份排序，`u64::MAX` 仍是有效时间。全源聚合完成后才应用分页游标，较晚到达的更早起点不会让身份遗漏或重复。名称来自最终元数据目录，保留歧义标记；CUDA 缓冲和只有 value 的事件不会被当作 CPU 区间。

桌面每页 1,024 项，最多保留 256 页返回游标，名称筛选仅作用于当前页。切换顺序会取消旧任务并清空旧页、返回历史与筛选缓存；换源恢复默认顺序。两类游标不能混用。首次开始时间查询失败后，可点“使用标识顺序”回到现有 key 分页；源变化、取消或资源超限不会发布部分目录。

## 读取成本与共同缓存

首次使用完整解码文件并建立目录索引。后续每页仍逐字节读取实际源文件，验证完整 BLAKE3 与长度，再读索引页；不再重复协议解码，但查询成本仍随源文件大小增长。游标绑定源身份、帧数和排序版本。原有 CLI/key 分页接口与内存来源语义保持独立。

目录和 [CPU 时间线索引](profile-disk-index.md) 共用当前工作目录的 `pvd-cache/profile` 根租约，分别使用 `catalog` 和 `index` 子目录。**1 GiB 是合并磁盘额度**，涵盖两份索引、归并时共存的临时输入和输出，以及必须保留并计量的残留；它独立于 TCP 的临时录制和热历史预算。

构建串行执行：先固定已完成 CPU 索引的实际大小，再从剩余额度建立目录。增加另一种索引能力会退休旧所有者，等待最后查询和后台清理归还根锁，再建立能力并集。只有全部成功才发布；失败的新增能力不进入永久并集，原有能力仍可单独重试。每次新增写入保留至少 512 MiB 可用空间，永久根控制锁的 39 字节遵循既有回收例外。

关闭、换源和退出会取消请求，旧句柄由后台任务释放，两个核心索引先于根租约销毁。正常结束为零索引数据文件，永久控制锁保留。未知内容和不能确认归属的残留按保守规则保留并占用额度，不能可靠计量时拒绝新建；不保证任意强杀残留全部自动回收，也不支持跨进程重开索引。

目录核心默认工作计量 64 MiB、排序 run 8 MiB，外部归并限制扇出。核心每页最多 4,096 项和 32 MiB 估算结果；桌面固定 1,024 项。Vec 实际容量、名称和节点估算纳入计量，解码器、运行时和分配器另有开销。并发查询各有额度，这些值不是全进程内存上限。

## 已完成验证

600 秒官方 SDK 捕获包含 251,301,039 字节、19,293 帧、3,275,660 条完成区间和 154,484 个事件身份。新目录与旧 key 分页的全部身份、名称、计数、最早起点及歧义标记逐字段一致，并核对全局顺序、每页游标和恰好一次出现。

大型目录验证应分页读取独立预期键，避免常驻完整目录。分别记录建库时间、索引峰值、进程工作集和退出清理，不将并行负载下的功能检查当作性能基准。

桌面需核对分页、CPU 查询、窄面板布局、共同额度、能力升级、旧查询取消、失败重试和未知目录保留。布局测试与离屏图片不能替代原生交互。

原版资料中的首次出现排序不足以确定聚合、未结束事件或相同 tick 的规则。本功能采用明确的项目排序定义，没有宣称精确复原原版算法。`PVDCAT01` 是派生缓存格式，不是原版 `.pxd2` 容器。
