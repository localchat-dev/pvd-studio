# OriginShift 场景与历史恢复

SDK 事件 28 和原版数据库事件 11 使用同一个场景更新入口。按当前代际有效的 Scene 成员引用平移：静态/动态刚体、Articulation 全部 Link 和 Cloth 更新 `GlobalPose` 位置，ParticleSystem/Fluid 更新 `Positions`。旋转、Shape 局部位姿、粒子速度及其他 Scene 保持原值，后续绝对位姿消息直接覆盖属性。

更新先按预算规划并验证布局，再提交属性动作。畸形布局、非有限位移、预算不足和取消在提交前失败。Articulation 遍历限制深度并记录已访问节点；过期引用不能平移复用地址的新对象。倒放恢复保存的旧值，不通过反向浮点加法推算。

## SDK 验证

[独立生产器](../tools/physx-origin-shift/README.md)在两个 Scene 中执行五次平移，用 SDK getter 核对刚体/Cloth 世界位姿、Shape 局部位姿及粒子位置和速度。显式 section 边界与物理模拟步分别记录。

专项比较内存、997 字节分块、三帧分段历史、正倒游标和随机定位，并将保留区间保存为项目捕获，释放原历史后重开核对。命令和输入由生产器说明提供；ignored 项需显式执行。

## 原版事件边界

已分析的 type 11 布局包含类型、实例 ID、三个 f32、u32 行数及每行八字节辅助数据。读取器在修改场景前检查完整长度、数量、尾部消费和取消；辅助撤销数据不用于本项目回放。参考文件身份见[证据登记](evidence.md)。

现有真实配对容器没有 type 11。SDK 真值和构造测试不能独立证明原版 OriginShift 容器互通。

范围为固定 PhysX 3.4.2 的上述对象。其他 SDK、GPU 粒子、自定义类型，以及查询/接触和已有绘制坐标的平移语义仍缺独立真值；未知类型或布局明确失败。首次冷定位和大规模平移仍受内存、磁盘和加载成本约束。
