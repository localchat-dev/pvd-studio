# OriginShift 场景与历史恢复

SDK 事件 28 和原版数据库事件 11 使用同一个场景更新入口。按当前代际有效的 Scene 成员引用平移：静态/动态刚体、Articulation 全部 Link 和 Cloth 更新 `GlobalPose` 位置，ParticleSystem/Fluid 更新 `Positions`。已捕获的 `WorldBounds` 两端减去位移，动态刚体的 `KinematicTarget` 平移位置，粒子 `ProjectionPlane` 的距离项加上法线与位移的点积。缺失属性不生成；旋转、Shape 局部位姿、粒子速度及其他 Scene 保持原值，后续绝对属性消息直接覆盖。

更新先按预算规划并验证布局，再提交属性动作。畸形布局、非有限位移、预算不足和取消在提交前失败。Articulation 遍历限制深度并记录已访问节点；过期引用不能平移复用地址的新对象。倒放恢复保存的旧值，不通过反向浮点加法推算。

`KinematicTarget` 只更新捕获中已有的变换，不恢复未传输的目标有效标志，也不放宽 RepX 对运动学目标的限制。

## SDK 验证

[独立生产器](../tools/physx-origin-shift/README.md)在两个 Scene 中执行五次平移，用 SDK getter 核对刚体/Cloth 世界位姿、Shape 局部位姿、有效运动学目标、粒子位置、速度及投影平面。显式 section 边界与物理模拟步分别记录。

固定 SDK 默认不发送 `WorldBounds`；专项通过 SDK DataStream 显式声明并提交 getter 值，后续由捕获中的平移事件更新，再与独立 getter 比较。包围盒 getter 的重算与逐次 f32 平移可能产生舍入差异，允许每分量 0.002 的差值；同份捕获的正倒/随机/磁盘回放仍逐状态精确比较。该专项不表示默认 SDK 流始终包含包围盒。

专项比较内存、997 字节分块、三帧分段历史、正倒游标和随机定位，并将保留区间保存为项目捕获，释放原历史后重开核对。命令和输入由生产器说明提供；ignored 项需显式执行。

独立空间数据专项使用两个 Scene、四次平移及后续模拟刷新。SDK getter、普通及批量 raycast/sweep/overlap 调用、命中结果、接触回调和 `getRenderBuffer()` 提供真值。每个 Scene 各有一组普通查询和两组批量查询，分别核对索引、查询几何、输入位置、命中位置/法线和对象引用。SDK 场景渲染缓冲随平移减去位移；已经送达的查询和接触保留最后一次调用或回调的坐标，直到后续模拟发送替换值。

绘制专项通过 `PvdUserRenderer::setInstanceId` 分别发送 instance=0 和明确绑定对应 Scene ID 的点、线、三角形与文本。每个标记帧重新提交图元，仅在标记 0、3、6 更新输入坐标，其余帧重发同组坐标，覆盖平移前发包、跨多次平移重发旧坐标和后续刷新；绘制范围遵循[同源前后 End 的窗口](frame-sources.md#绘制窗口)，不按其他来源的 End 清空。实例 ID 标记与包内坐标独立：SDK 的此接口仅序列化给定 ID 和坐标，项目保留发包位置，不以绑定 Scene 为由重复平移。该专项也覆盖分块、磁盘分段、正倒/随机回放及清理源历史后重开项目捕获。

`PxPvdSceneClient::drawPoints/Lines/Triangles/Text` 的创建来源不等于线上 Scene 归属。固定 SDK 的 `SceneRendererClient` 只创建 renderer 并写入 `events`，没有创建 Scene→renderer 属性或自动设置 Scene ID；约束绘制还会设置当前实例 ID。不能把该接口的调用对象当作所有后续图元的坐标归属。显式绑定专项不证明原版界面如何转换这些坐标，也不外推其他 SDK 的行为。

## 原版事件边界

已分析的 type 11 布局包含类型、实例 ID、三个 f32、u32 行数及每行八字节的辅助实例/属性对。原版 factory 将这组数据用于回溯链；读取器在修改场景前检查完整长度、数量、尾部消费和取消，辅助行不用于本项目回放。参考文件身份见[证据登记](evidence.md)。

原版静态属性更新路径包含世界位姿、包围盒、运动学目标和粒子投影平面。项目粒子位置的更新另由固定 SDK getter 配对支持；静态路径和 SDK 真值不合并为原版全部对象的行为声明。

[整份保存与受限刚体裁剪](native-export.md)保留该事件的原始位模式和辅助行；前缀同时保留原事件号与撤销引用，不重算属性字节。中段仅支持可逐位逆转的平移，且不含保存实例或指向 type 11 的属性撤销依赖；首帧标记和源快照另有限制。多页、非空初始快照的整份保存、截断及裁剪边界由构造专项覆盖，不代替真实原版互验。

现有真实配对容器没有 type 11。SDK 真值和构造测试不能独立证明原版 OriginShift 容器互通。

范围为固定 PhysX 3.4.2 的上述对象和空间数据。其他 SDK、GPU 粒子、自定义类型及原版绘制坐标消费仍需独立真值；相机没有可用的 Scene 归属信息。未知类型或布局明确失败。首次冷定位和大规模平移仍受内存、磁盘和加载成本约束。
