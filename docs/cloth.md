# PhysX 3.4 PxCloth 捕获与显示边界

验证范围为 Windows x64、官方 PhysX 3.4.2 checked、固定提交 `5e42a5f112351a223c19c17bb331e6c55037b8eb` 的 CPU Cloth 与 PVD ALL。模拟器只属于独立生产器。

## 能力矩阵

| 数据/功能 | 证据 | 状态 |
| --- | --- | --- |
| 当前粒子位置、inverse mass | S/T：`updateCloths` 的 ParticleBuffer 与 SDK `lockParticleData()->particles` | 解析、回放、局部/世界坐标 iterator，通过 2,520 个粒子核对 |
| Cloth 全局姿态、sleep、Fabric 引用 | S/T：PxCloth 元数据与直接 getter | 平移/旋转、主动睡眠/唤醒、离场重入 generation 通过 |
| Fabric 约束拓扑 | S/T：getParticleIndices/getRestvalues/getSets/getPhases | 约束边、原长、求解集合与阶段，9,000 条世界约束边对照通过 |
| Fabric 共享 | T：两个 Cloth 指向同一 Fabric | 解码结果使用共享 Arc；缓存键包含 id 与 generation |
| solver previousParticles | S/T 缺失：发送器只写 particles，真实类元数据无 PreviousParticles | 明确 `previous_particles=None`，不能从相邻捕获帧替代 |
| 布料表面三角形/四边形 | S/T 缺失：Fabric 元数据只有约束索引，真实流无 Triangles/Quads | 无三角面显示；使用真实粒子与约束线，不从约束图猜表面 |
| Fabric 同地址释放/重建 | T：特定共享/离场重入序列留下旧元数据 | 检测到 Cloth/Fabric 粒子数量冲突时明确诊断，拒绝使用旧约束 |
| APEX Clothing、GPU Cloth、其他 SDK | 未验证 | 独立类别/数据方向，不在本通过范围 |

`ParticleIndices` 是每两个粒子构成的约束，不是三个索引构成的三角形。Fabric 的弯曲/剪切约束也不能当成表面边。`CollisionTriangles` 是碰撞形状；`VirtualParticles` 是额外碰撞采样数据，同样不能作为完整布料表面拓扑。

SDK 的 `previousParticles` 表示前一次求解迭代，而不是上一帧采样。真值包含这一数组以证实缺失的数据是什么：测试确认它既不同于当前 particles，也不同于前一捕获帧；程序不生成伪造速度或假 previousParticles。

## 核心接口与边界

`cloth::collect(&SceneState)` 返回 `ClothFrame`：cloths、粒子/约束实例总数、唯一 Fabric 数和诊断。Cloth 中保留对象 generation、全局姿态、sleep、粒子及共享 Fabric，提供 `world_position(index)`、`world_positions()` 和 `world_constraints()`。原始元数据继续保留在 `SceneState` 中。

解码 `physx3::PxClothParticle` 和 `physx3::PxClothFabricPhase` 时验证记录长度并尊重字节序；未知结构不猜布局。显示收集验证 counts、有限位置/质量/原长、四元数、约束索引范围、累计 Sets 和 Phase 的类型/集合引用。Fabric 引用按捕获时 generation 解析，禁止绑定已经复用的旧地址。

每次收集限制 4,096 个 Cloth、128 MiB 解码数据、每个 Fabric 1,000,000 粒子和 1,500,000 约束/阶段/集合项。共享 Fabric 只计一次，粒子按 Cloth 分别计费。超限或无效元数据带对象 ID/generation 报告；已成功恢复的其他 Cloth 保留显示能力。`render_scene` 说明该类缺少表面拓扑，不妨碍单独的 Cloth 点线视图。

## 真值与帧边界

`tools/physx-cloth/cloth.cpp` 创建非对称、固定上边粒子的 4×5 网格，两个 Cloth 共享 Fabric，使用不同世界旋转与平移。第 20 帧改变姿态，第 30 帧将一个 Cloth 从 Scene 移除后重新加入；第 45 帧切换到 3×4 粒子的新 Fabric，第 60 帧主动入睡，第 68 帧唤醒。

Fabric 真值来自 SDK getter；粒子和 inverse mass 来自 SDK read lock；世界坐标由 SDK `PxTransform::transform` 计算，不使用本项目的坐标实现。主样例在释放旧 Fabric 前分配新 Fabric，检验有独立身份的资源切换；原 Fabric 释放通知的限制由单独探针覆盖。

`ScbScenePvdClient::frameEnd` 在发送 EndFrame 前调用 `updateCloths`，因此 Cloth 当前粒子对应本次 fetchResults 后状态，与 rigid Actor/ArticulationLink 的位姿发送阶段不同。测试在 `context.step()` 后读取 SDK 真值，不对录制事件重新排序。

核心验证覆盖全部 75 帧、顺序重建与检查点一致、反向逐帧、随机边界跳转、共享资源、对象销毁/重建、睡眠期间 ParticleBuffer 保留、截断、畸形元数据、过大长度及精确分配预算边界。

## Fabric 地址复用探针

`--reuse-fabric-address` 在第 45 帧后释放并重建 Cloth/Fabric。固定输入曾出现 SDK 复用 Fabric 地址、流中仍保留旧元数据而新 Cloth 粒子数已变化的情况。解析器不能把不匹配的 Fabric 当作有效表面或约束。

这是一份独立真实异常流。测试要求第 45–74 帧产生 `Cloth and Fabric particle counts disagree`，不应用旧 Fabric 约束，也不修改流来制造匹配。已记录的原始对象属性仍可检查。

源码线索：`createInstance(PxCloth)` 对 Fabric 调用 `registerObject`，`destroyInstance(PxCloth)` 移除 Cloth 引用；`PvdPhysicsClient::onNpFactoryBufferRelease` 调用 `unRegisterObject`。共享、重入和引用计数的组合与观察到的未重建行为吻合，但本项目未修改 SDK，也未完成所有组合的归因。

同样粒子数、不同约束但缺少新元数据的地址复用，不能仅凭记录可靠识别。保留该限制，不声明可以恢复发送端遗漏的信息。旧 Fabric 如果没有 DestroyInstance，会作为捕获中的无 Cloth 引用对象保留；不能凭本地 SDK 真值擅自删除用户录制中的对象。

## 复验

在项目根目录运行：

```powershell
./tools/physx-cloth/verify.ps1
```

脚本构建固定 SDK 的生产器，在新的 `output/cloth-validation/<timestamp>` 目录生成正常/异常两套流与 JSON，执行 3 个常规核心测试和 2 个显式 ignored SDK 测试。`-SkipBuild` 复用生产器。已有输出拒绝覆盖；环境变量在结束后恢复。只运行后台进程，不打开原版或桌面窗口。

单独测试使用 `PVD_CLOTH_CAPTURE`、`PVD_CLOTH_REUSE_CAPTURE`；默认样例分别为 `captures/physx-3.4-cloth.pvdstream` 和 `captures/physx-3.4-cloth-reused-fabric.pvdstream`，真值使用同 stem 的 `.cloth.json`。默认 `cargo test` 不执行这些 ignored 测试。

## 官方源码证据

- `PhysX_3.4/Source/PhysX/src/PvdMetaDataPvdBinding.cpp`：PxCloth/PxClothFabric 元数据，sendAllProperties、updateCloths、createInstance/destroyInstance。
- `PhysX_3.4/Source/PhysX/src/buffering/ScbScenePvdClient.cpp`：frameEnd 中 Cloth 数据与 EndFrame 的发送顺序。
- `PhysX_3.4/Source/PhysXMetaData/core/include/PxAutoGeneratedMetaDataObjects.h`：Fabric 的 Phases/Sets/ParticleIndices/Restvalues 集合。
- `PhysX_3.4/Include/cloth/PxClothParticleData.h`：previousParticles 为前一次迭代的数据。
- `PhysX_3.4/Include/cloth/PxClothFabric.h`：约束索引、Sets、原长的定义；`PxClothFabricDesc` 的 triangle 数据不等于 PVD 已发送该字段。
- `PhysX_3.4/Source/PhysX/src/PvdPhysicsClient.cpp` 与 `NpFactory.cpp`：Fabric 释放/注册路径。

所有范围均为上述固定提交的 CPU PxCloth，不外推到 APEX Clothing 或其他 SDK。原版 PVD3 保存容器、原生交互和表面拓扑恢复尚未验收。
