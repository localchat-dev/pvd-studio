# 实现路线图

参考目标为 NVIDIA PhysX Visual Debugger 3（PVD3）的功能与工作流程。主要验证路径为 PhysX 3.4.2；其他 SDK、APEX 和 GPU 数据按独立范围建立证据。OmniPVD/`.ovd` 属于单独的兼容方向。

本计划区分缺少实现与缺少验证。优先级表示推进顺序，不表示完成日期；范围、依赖或证据变化时同步更新[功能清单](manual-checklist.md)和[兼容矩阵](compatibility.md)。

功能概况见[项目状态](current-status.md)。本文维护未完成工作的稳定编号和完成条件。

## P2：产品与规模验收

Unity 编辑器插件需在真实地图验证切图叠加、脚本重载、退出和长时间负载。用同一捕获对比停止监听、仅实时查看、完整录制时的主线程帧耗时和接收积压，分别测试窗口开关。专项步骤见 [Unity 插件](unity.md#验证)。

长录制已提供分段导入与导出。现场验收应在目标地图导出正在接收的会话，并在另一台机器只复制并打开保存的 .pvdcapture 文件，核对分段边界两侧的帧和定位耗时。

| 编号 | 当前边界 | 工作与完成条件 |
| --- | --- | --- |
| PRODUCT-01 | 面板排序、分栏、浮动、关闭/恢复与保存已接通；工具栏文字缺失报告离屏未复现 | 补齐原生文件/保存对话框、剪贴板、引用跳转、曲线与停靠操作、动态 DPI、其他 IME 和焦点路径 |
| PRODUCT-02 | 本地真实回环与有限长跑已有记录，用户远端场景未验收 | 在真实跨机器负载下同时接收和正倒放，分别记录解析、模型提交、GPU 完成、积压及历史窗口；保持真值和退出清理检查 |
| PRODUCT-03 | 文件生命周期及同步/异步真实 TCP 的多来源滚动、回放、保存重开和清理已有验证；封存中取消和五种后台清理退出场景已验，停滞来源及准备失败回收有构造回归 | 补齐真实写入缺口、停滞来源、长时间连接和保存负载，以及原生窗口退出、GPU 显存与进程资源趋势 |
| PRODUCT-04 | 原版、C++ 与桌面版已对照[空场景内存](validation.md#空场景内存)及[大型场景拖轴、换向和连续回放](validation.md#大型场景回放)；分卷预读和刚体变换复用已通过大型捕获的离屏正倒放检查 | 统一视图设置并扩大原生手势采样，分别测量冷定位、热步进、持续接收和原生显示 |
| PRODUCT-05 | 任意上轴、Gravity 自动判断、重置相机、Shift 多选、性能条曲线入口、状态配色、休眠/触发器范围及帮助有实现；选择手势、默认配色、图页和部分设置行为不同 | 按手册第 6–11 页核对完整原生操作、自动上轴算法、滑块范围与速度单位。项目帮助及问题渠道使用本项目资料 |

桌面与 Unity 的同端口共享已有本机原始流验证。真实地图验收分别记录两个窗口的帧时间、共享接收积压及持有端口的一端退出后发送端的重连时间。方法见[同端口共享接收](validation.md#同端口共享接收)。

自动化优先使用 CLI、真实 SDK 和无窗口渲染。操作系统输入、DPI 与原版打开互通只在对应环境中验收；自动化不能覆盖时明确保留待验状态。

## 完成规则

1. 实现有明确的数据来源、格式/版本边界、错误行为和资源限制。
2. 记录输入身份、源码或提交身份、实际命令和结果；忽略项与失败记录单列。
3. 同帧对象、属性、引用、分析与显示保持一致，错误/取消不发布半成品。
4. 格式声明需要外部交叉验证；文件原版可打开不等于全部语义一致。
5. 提交说明记录已经落地的变化和当前限制，完整后续计划在本文维护。
