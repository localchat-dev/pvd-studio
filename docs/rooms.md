# 多物理场景调试

同一 PVD 会话中的独立 `PxScene` 显示为“物理场景 1、物理场景 2……”（英文为 `Physics Scene N`），适用于 Go 经 cgo 调用 PhysX 3.4 等接入方式，无需业务侧另外提供编号。物理场景切换控制查看范围；TCP 接收、解码和保存仍覆盖整条会话。

## 界面与操作

物理场景列表位于左侧对象树上方，列表和视口使用同一编号。原始 `PxScene` ID 与对象代际在悬浮说明中显示；界面编号不是业务原名。中央保留一个主视口，右侧为属性和显示设置，播放控制位于顶部第二行。

- 单击物理场景切换查看目标；列表可收起、滚动和筛选已销毁项，较长列表提供显示编号或 Scene ID 搜索。
- 视口、对象树、选择范围与回放位置一起切换。等待目标完整帧时保留当前显示，并提示正在等待的物理场景；失败或取消不发布半次切换。
- 暂停时按当前捕获位置寻找目标物理场景之前最近的完整帧；没有更早帧时使用其首个保留帧。实时切换等待目标来源的完整帧。
- 新建物理场景不抢占当前选择。当前物理场景销毁后停止跟随实时，保留最后画面及可用回放；没有完整帧历史时给出提示。
- 每个物理场景记忆相机位置，首次进入时聚焦其内容；会话切换清空这些视角，最多缓存 256 个。
- “全部场景”显示当前捕获位置的完整状态，包括无法确定物理场景归属的调试绘制。

列表的刚体数量最多每半秒更新一次，取自最近发布的快照，不是每个物理场景独立的最新收包状态。多个 Scene 的模拟时钟不强行对齐，列表和全部场景视图不表示同一物理时刻。

## 身份与回放

身份由会话、Scene ID 和对象代际组成。编号按首次观察顺序分配，切换、暂停和倒放不重排；销毁后同地址创建的 Scene 获得新编号。自动编号不是跨录制的业务 ID，重新连接或打开 SDK 裁剪片段可以重新编号。

SDK 与带来源目录的 PVDCAP03 按物理场景的实际完成边界定位、逐帧和正倒放，不跨到同地址的新代际。每个来源使用缓存的代际边界和二分定位；导航只访问仍可读取的完整帧。来源内序号与全局索引的区别见[帧来源](frame-sources.md)。

原版数据库及旧项目捕获的 `Legacy` 轴不包含独立 SDK 来源。物理场景显示仍按身份隔离，回放使用可观察生命周期内的共享录制帧轴，不声称恢复了缺失的物理场景时钟。事件组的 `stream_id` 不是物理场景 ID。

## 生命周期与历史

“已销毁”仅依据捕获中完整解析的销毁事件。生命周期目录独立于显示位置和 `End` 边界，因此首帧前及最后一帧后的销毁也能更新列表，不伪造物理帧。倒放不会撤回最新已确认的销毁结论。

| 状态 | 含义 |
| --- | --- |
| 在线 | 连接仍在，未观察到该物理场景销毁 |
| 已销毁 | 已解析到该 Scene 代际的销毁事件 |
| 已断开 | 连接结束，未确认该物理场景销毁 |
| 无历史 | 没有可用的完整帧；可能尚未完成首帧或历史已淘汰 |
| 录制 | 文件中可观察到的物理场景，不表示源端当前状态 |

销毁和历史可用性分别判断：已销毁物理场景仍可回放，存活物理场景也可能没有保留帧。长时间没有更新不推断为暂停或销毁。

目录最多保留 4096 个摘要，优先回收最早的已销毁项；全部为存活摘要时省略新增摘要，并显示省略数量。摘要回收不复用编号，也不改变接收或历史内容。目录使用独立的有界内存，不计入默认 512 MiB 历史内存预算；这些预算均不代表整个进程的内存上限。

## 显示范围

物理场景范围在对象收集之前生效，避免为其他物理场景生成网格后再隐藏。范围按 Scene 代际及对象关系缓存，使用捕获中的有效引用。

| 数据 | 范围 |
| --- | --- |
| 刚体、布料、粒子、Articulation Link | 实际 Scene 归属；Link 经 Articulation 关联 |
| Shape、材质、网格 | 当前物理场景所需依赖；共享资源可以属于多个物理场景 |
| 查询与接触 | 捕获中的 Scene 归属 |
| SDK 调试绘制及文字 | 在“全部场景”查看；裸实例 ID 不足以证明物理场景及代际 |
| 对象树与搜索 | 当前物理场景及其有效依赖；跨范围引用不直接切换对象 |
| 选择、跟随、RepX | 清理范围外选择；属性面板导出有效选择及依赖，帧导出保留全部物理场景 |
| 场景统计与上方向 | 当前显示物理场景的对象及 Gravity |
| 性能、内存、错误 | 保持各自分析范围，不自动拆分为物理场景数据 |

录制相机缺少 Scene 关联时保持全局，不推断归属。

## 保存与资源边界

含物理场景目录的 PVDCAP03 使用内层元数据版本 2，保存编号、Scene 代际及观察到的创建/销毁位置。保存到捕获末端时包含末帧后的生命周期摘要；截取较早区间时排除后续创建，并不带入后续销毁结论。帧索引仍沿用源录制坐标。

读取兼容元数据版本 1。旧数据仅从首帧状态及已有帧来源恢复可观察物理场景，无法恢复未保存的末尾生命周期或原始创建顺序。不支持元数据版本 2 的旧程序会明确拒绝含该目录的文件。保存流程与其他格式限制见[保留捕获](retained-capture.md)。

同一连接的物理场景共用一份[完整临时录制](temporary-recordings.md)。某场景销毁后保留其已有帧，同连接其他场景继续录制；热缓存回收不删除已封存前史。清理以已结束的整条录制为单位，不单独删除仍可能被其他场景引用的共享数据。接收积压和永久原始录制另行计量，见[接收策略](receive-backpressure.md)。

单物理场景显示减少场景提取、对象树和渲染成本，不减少 TCP 字节、完整解码或历史写入。按物理场景删减数据和历史降采样尚未实现，也不会自动启用。不能任意丢弃增量事件：类型、字符串、生命周期、分块属性及共享资源可能被其他物理场景依赖。

PhysX 3.4 的 Scene PVD 标志控制接触、查询和约束可视化；它们不是完整的单物理场景禁发开关。连接级 DEBUG、PROFILE、MEMORY 开关也不按物理场景区分。
