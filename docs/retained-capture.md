# 保留历史捕获

“保存保留历史”将当前仍可读取的场景和分析区间保存为 `.pvdcapture`。读取 `PVDCAP01` 至 `PVDCAP04`；保存时根据可见区间和单段容量自动选择 03 或 04。源会话释放并清理临时历史后，文件仍可独立打开。

这是项目格式，与 SDK communication stream、PVD3 原版数据库和内部临时历史格式不同。它不提供 PVD3 互通，也不包含完整 SDK 原始字节。

时间轴的“保存录制”可直接保存磁盘历史中的全部可用帧，不要求开启自动原始录制；正在接收、暂停显示以及断开后仅留下 `.partial` 原始文件时均可使用。路径与选择器使用 `.pvdcapture`，保存过程不停止 TCP 接收。需要指定更小范围时，仍可使用“片段 → 保存保留历史”。内存 SDK 文件的同名保存按钮复制完整 `.pvdstream`；磁盘来源的完整原始文件另存在“原始流”菜单。

项目捕获默认写入当前工作目录的 `captures/capture.pvdcapture`，原始流和 SDK 片段默认使用 `captures/capture.pvdstream`。保存及打开对应保存选择器会创建所需父目录；手动指定的路径按原值使用，创建目录失败或目标已存在会报错。

## 分段导入与导出

桌面时间轴点 **保存录制**，或在 **片段 → 保存保留历史** 指定首帧和末帧。Unity 的导出入口见 [Unity 插件](unity.md#导出给桌面-studio)。两端均输出一个 `.pvdcapture` 文件。复制这一个文件，在桌面 Studio 中直接打开即可按原始帧号正放、倒放或定位。

默认最多 4,096 个可见帧且符合单段容量的区间保存为 `PVDCAP03`，支持 03 的旧版 Studio 仍可打开。更长的区间，或资源索引超出一段预算的区间，会使用 `PVDCAP04`。04 将独立可恢复的数据段和定位目录放在同一个文件中，需要支持 04 的 Studio。打开时校验目录及分段，回放按所需段读取。保留早期 `.pvdset` 录制时，应连同其原有分片目录一起打开，可再保存为单文件。

## 范围与时间

- 保留源会话中的全局帧索引、SDK ticks、Scene ID，以及来源键和来源内序号，不把区间重排为零起点。
- 只允许定位保存的可见范围，不开放为恢复保留的隐藏前缀。
- 原始 ticks 和帧间隔继续保留。相对时间以该来源首个可见帧为零点，Legacy 使用录制首个可见帧；隐藏恢复前缀不参与计时，见[帧来源](frame-sources.md#两种帧号)。
- 首帧恢复可能依赖之前的基线、资源和分析事件，因此输出大小不一定随可见帧数同比缩小。
- 再次裁剪只从当前可见范围选择，不补造已淘汰或不可见的前史。

03 使用独立来源目录，与可见帧逐项对应；隐藏恢复前缀不进入导航目录。旧 01/02 没有原始 section 来源信息，使用 `Legacy` 录制帧轴，重存不会推断出缺失来源。来源切换和两种帧号见[帧来源](frame-sources.md)。

含房间目录的捕获使用内层元数据版本 2；编号、生命周期、区间截取和旧版读取边界见[多房间调试](rooms.md#保存与资源边界)。

项目捕获可以通过桌面或 CLI 的 `inspect`、`verify`、`frame` 等读取入口打开。桌面提供保留区间保存和再次裁剪；核心入口为 `pvd_core::capture::{write_portable_new, open_with_progress}`。CLI 的 SDK `trim` 不是项目捕获裁剪入口。

## 写入与取消

目标必须不存在。输出使用同目录临时文件，完成写入、校验和同步后无覆盖发布。取消、错误或目标竞争不覆盖已有文件；导出只能清理自身的临时文件。

完整临时录制的导出覆盖冷存储块与当前热历史，相关读者释放前不清理所需临时数据。显式滚动模式仍可能淘汰导出区间；若租约失效，保存失败并清理临时输出，接收会话继续运行。保存不会自动启用永久原始录制，也不能恢复已经丢失的原始字节。

## 资源边界

核心 `CaptureLimits::default()` 为索引 64 MiB、输出 8 GiB、100 万帧、1,048,576 个资源。桌面保存完整临时录制时不再使用 8 GiB 输出字节限额，而以剩余磁盘空间约束写入；文件读取按实际长度放行字节大小，索引、帧数和资源数量的限制仍然保留。每个 03 数据段的来源目录与其他段内索引共用预算，编码字节和解码目录的共存空间计入限制。04 文件另设全局帧与分段目录预算，全局来源导航独立计量，最高 64 MiB。历史单条记录及资源块还有独立限制。外部记录解码具有累计分配和深度限制，不能由这些计量推断应用的 RSS 上限。

04 对各段单独计量帧目录与资源，跨段共用的恢复数据可能占用多份磁盘空间。单帧及其恢复依赖仍须能放入一段，全会话导航和可用磁盘空间也有限制。需要完整 SDK 原始字节时须事先启用原始流录制。

内部持久 Scene Undo 不写入项目捕获。重开使用捕获中的恢复数据保证正倒/随机结果一致，不承诺与直播历史撤销路径相同的耗时。

## 不提供的操作

项目捕获不包含完整 SDK 原始流，因此完整原始文件另存、SDK 原始流裁剪、全源分析 CSV 和完整文件事件目录入口会明确拒绝。当前可见区间内的状态、分析和回放仍可使用。SDK 片段定义的 JSON sidecar 不适用于项目捕获。

原版容器的写出和任意区间裁剪见[路线图](roadmap.md)，不能通过重命名项目捕获文件实现。

## 验证范围

验证覆盖 01/02/03 读取、再次裁剪、完整 Scene/Analysis 对照、取消/源失效/无覆盖发布，以及释放源历史后重开。03 另覆盖双来源保存/重开/再裁剪、各来源可见时间零点、旧版重存、可见帧精确对应，以及重算外层校验和后仍拒绝缺失、重复或篡改的来源目录。真实 APEX 同步与异步捕获的重开状态已逐帧对照 SDK getter。OriginShift 专项进一步逐位核对双 Scene 的位置、旋转、局部姿态和粒子位置/速度，保存后独立重开全部保留状态。

04 的回归覆盖单文件移动后独立重开、跨段正倒定位、保留区间再裁剪、分段目录损坏，以及两侧分段采用不同局部偏移时的场景与分析恢复。Unity TCP 探针发送 8,200 帧，清理临时缓存后保留一个文件，可供桌面或 CLI 在另一目录复核。

入口与可重复方法见[验收方法](acceptance-plan.md)、[OriginShift](origin-shift.md)及[验证说明](validation.md)。这些结果不扩大 PVD3 格式兼容范围，也不作为持续 TCP 或原生窗口帧率的结论。
