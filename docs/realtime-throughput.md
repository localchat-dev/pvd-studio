# 持续活动场景的实时吞吐

持续活动场景需要处理速度跟上实际输入，同时保留真实历史、回放一致性和资源上限。扩大接收缓存只能推迟容量耗尽，不能消除长期积压。当前的数据路径与优化机制见[架构](architecture.md)和[吞吐优化](throughput-optimization.md)。

## 分层测量

| 层次 | 测量边界 |
| --- | --- |
| 来源 | 同一 SDK 负载的模拟、序列化、发送及来源自身等待 |
| TCP | 实际接收字节、接收缓存与排空，不包含解码 |
| 协议 | 字节到事件组，保留分块和输入摘要 |
| 模型与历史 | 状态应用、增量捕获、预留、序列化、压实与提交 |
| 发布与显示 | 合并、UI 应用、Bevy 更新、GPU 完成及窗口呈现分别记录 |

初始化、稳定活动、来源结束后的排空分别统计。物体休眠后的扫尾会提高整段平均速度，不能用总帧数除总时长替代稳定阶段吞吐。生产器的 `--interval-ms 16` 也不保证来源达到 60 Hz。

诊断探针会应用 `SceneUpdate` 并比较位姿，未执行 Bevy/GPU 渲染；这部分开销应与桌面区分。入口及参数见[诊断工具](../tools/README-live-probe.md)。

## 代表性负载

使用[独立 SDK 生产器](../tools/physx-sample/README.md)生成小、中、大活动集合，组合静态共享几何、持续动态位姿、运动学体/CCT、常驻分配和分析事件。记录 SDK 活动统计，不能只用 `IsSleeping=false` 证明整个负载持续活动。

DEBUG 和 ALL、永久原始录制开关分别测试。同机回环与跨机器分开报告。覆盖创建/销毁、ID 复用、引用变更、多 Shape、大资源及共享快照；多 Scene 的异步语义单独验收。

正确性核对包括输入字节、帧数、同帧对象与分析、顺序/随机/反向恢复、检查点和淘汰边界。最终状态一致不能替代中间帧核对，字节数相等不能替代内容一致。

## 并发回放检查

构建 SDK 生产器后，可运行无窗口 TCP 专项：

```powershell
$env:PVD_SDK34_SAMPLE = (Resolve-Path '.deps/physx-sample-build/Release/pvd-physx-sample.exe').Path
$env:PVD_PLAYBACK_PROBE_OUTPUT = Join-Path (Get-Location) ('output/tcp-playback-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$env:PVD_LONG_PLAYBACK_SECONDS = '300'
cargo test --locked -p pvd-desktop studio::playback_tests::real_sdk_tcp_ui_demand_scene_playback_and_paused_analysis_match_permanent_raw -- --ignored --exact --nocapture --test-threads=1
```

每段历史回放要求同一会话的核心提交和界面帧计数均推进，持续核对相邻步、分析需求和淘汰边界。达到目标步数后最多再观察 5 秒，期间保持同向历史回放；自然到达实时边界时只接受转实时之前的进度。这是并发推进检查，不是固定帧延迟保证。

输出包含阶段计数边界、原始捕获及重新解码的状态对照，结束时检查积压和所属历史文件释放。该路径不包含 GPU 或原生窗口；`PVD_TCP_REPLAY_TRACE=1` 额外记录详细计时，包含计时自身开销。

## 时间基准与资源

同一接收进程使用单调时钟记录接收、解码、历史提交、发布和显示应用。数据块没有天然的物理帧标识，可按帧结束事件的字节偏移关联接收块，并明确测量粒度。

SDK 时间戳具有独立时钟比例，跨机器绝对时间不能直接相减。端到端来源延迟需要可验证的时钟对齐。`queued_bytes=0` 也可能仍有已交付、正在处理的数据。

至少记录接收积压、已解码/显示帧差、核心预算、进程 RSS/私有内存、CPU、GPU 和磁盘趋势。持续接收、回放、保存、容量淘汰、取消与失败恢复应在同一负载下组合检查；验收条件见[路线图](roadmap.md)。

## 异步历史的设计边界

当前帧完成路径同步提交历史后再发布显示补丁。若引入独立历史写入线程，需要分别维护最新解码帧与最新可读历史帧：队列持有不可变增量，按字节与元数据限额，并按帧序提交。完整记录、索引和 flush 成功后才能发布读取边界。

写入失败只能保留最后有效边界，恢复需要完整基线；暂停留存产生的缺口必须显式表示。`flush` 不等于断电持久化保证。异步写入属于设计方向，不作为已实现能力。
