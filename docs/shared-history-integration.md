# 历史一致性验收

历史存储的设计见[共享历史](shared-history.md)与[分页分析](resident-analysis.md)。本文定义整体验收口径，当前结果见[验证说明](validation.md)。

## 一致性

- 对照独立 SDK 原始前缀核对完整场景、分析、内存存活状态及 Churn，不只比较对象数或可见图像。
- 覆盖首次、相邻正倒、跨段、随机恢复、缓存外定位及同帧场景到完整分析升级。
- 滚动淘汰后检查最早保留帧、过期请求、旧显示根和资源租约；保留旧画面不表示旧历史仍可加载。
- 项目捕获需在源历史释放后独立重开、定位并再次裁剪，保留原始帧号与可见范围。

## 资源与退出

记录历史物理字节、整理预留、预算域、缓存元数据和进程/GPU 资源，分别说明计量范围。固定小预算检查保留原有断言，不以提高额度通过。

取消、换源、连接结束和进程退出后检查自有临时负载。固定控制锁与历史负载分别统计，未知文件和其他会话不得删除。

## 持续接收与显示

TCP 回放期间持续检查解码推进、接收积压、raw 真值和退出清理。场景按需模式与完整分析模式分别执行。离屏检查需取得对应目标的 GPU 完成回执，并核对 UI/Scene 帧号及图片。

核心 API、模型提交、离屏回执和原生显示分别计时。冷定位说明缓存条件；比较磁盘占用时固定保留范围。功能检查通过不自动成为性能对照结果。
