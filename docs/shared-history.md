# 共享历史存储与回放

历史由 `pvd-core::live` 管理，不依赖界面。默认根目录为当前工作目录的 `pvd-cache/history`，滚动上限 8 GiB。接收缓存、永久原始录制和性能索引分别管理。

## 存储与提交

内部缓存 `PVDHIS03` 按时间分段保存帧增量和目录；对象版本、大属性、绘制、接触及分析页进入会话共享资源仓库。内容分块以 BLAKE3 和实际字节复用，分段持有资源根。分析输入保留接收顺序。

帧索引每页 256 项，完成页不可变。写入先提交资源及依赖，再提交帧和检查点，最后发布目录；失败不发布半帧。资源目录依赖当前会话，临时缓存不作为独立持久数据库使用。独立重开使用[项目捕获](retained-capture.md)。

## 滚动与边界

淘汰分段使其租约失效，旧快照不能钉住过期历史。正在进行的读取只保护该次所需文件。回收按实际删除扣除占用；混合文件在有界预留空间内整理，退休文件、写入失败尾部及删除失败均计入物理预算。

每帧的跨段重试共用一次机会压实额度；有完成段时，额度耗尽后淘汰历史，没有完成段时允许容量救援。该策略不承诺任意输入的 I/O 耗时上限。

| 资源 | 边界 |
| --- | --- |
| 帧 / 完成分段 | 1,000,000 / 4,096 |
| 资源文件 / 待删除空段 | 4,096 / 64 |
| 单记录 / 单事务 / 依赖深度 | 64 MiB / 640 MiB / 64 |
| 资源文件目标 | 磁盘预算的 1/32，限制在 256 B–8 MiB |
| 元数据 | 随预算分档，默认历史预算对应 512 MiB 计量额度 |

帧数、元数据或当前场景预算可能先于磁盘上限限制保留范围。容量不保证固定保留时长，也不是进程或 GPU 内存上限。清理仅处理经所有权标记、签名与锁验证的自有缓存。

## 连续恢复

正放应用下一帧变化，跨段保留游标。倒放优先使用最多 120 帧/8 MiB 的索引撤销缓存，再使用已提交的持久 Scene Undo，缺失时从检查点恢复。撤销仍受历史租约约束；取消、换源或未发布结果被替换时清除对应游标。

Resident 分析缓存最多保留 120 个完成根，负载统一计入会话 192 MiB 预算域；Legacy 缓存最多 32 条/192 MiB。分析恢复与场景撤销独立：命中完成根可直接切换，未命中需恢复不晚于目标的分析基线并向前重放。

首次和随机冷定位仍有基线成本。持久 Scene Undo 不代表完整分析逐帧撤销，也不写入项目捕获。
