# TCP 历史压实与回收

历史写入在追加、检查点和分段切换时预留容量。一次帧追加可能跨段重试，这些重试共享一次机会压实额度，避免在同一帧反复执行昂贵的压实。

存在已完成历史段时，机会额度耗尽后优先淘汰旧段；没有已完成段时仍允许容量救援。磁盘与内存预算、候选选择、I/O 错误处理和解码推进检查保持独立。该策略可能缩短保留范围，不提供任意输入下的硬时延保证。

## 验证要求

使用[SDK 混合负载](../tools/physx-sample/README.md#大量常驻分配与小分析缓冲)，在较小的历史预算下同时接收、正倒放和暂停补齐分析，覆盖：

- 段首、检查点和压实期间的解码与显示推进。
- 滚动淘汰、保留旧快照、读取取消、磁盘空间不足和失败回收。
- 同次原始流的场景状态、内存/Churn 和所选性能区间核对。
- 正常退出后的接收积压、后台任务和临时文件清理。

性能报告分别记录首次定位、相邻正倒步进、过期跳跃和跨阶段请求。模型应用间隔包含调度及观察成本，不能等同于核心 seek 耗时、GPU 完成时间或窗口帧率。不同保留范围、输入长度和结束时刻的结果不构成等条件对照。
