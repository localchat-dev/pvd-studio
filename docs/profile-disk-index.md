# 完整 SDK 录制的 CPU 时间线索引

完整 SDK 文件的 CPU 时间线与流式查询使用派生磁盘索引，Windows 桌面按文件身份管理缓存。首次开始时间目录与其共用额度，见[目录索引](profile-catalog-index.md)。

Windows 桌面在完整 SDK 录制的“性能 → 线程时间线”首次载入时间窗时建立磁盘索引。同一份已打开录制的后续窗口复用索引。线程目录仍单独扫描完整源，因此首次线程目录和首次建库各有一次完整协议解码。事件目录的首次开始时间排序使用另一份派生索引，共享根租约和合并额度；标识分页、曲线和原版数据库不由 CPU 时间窗索引加速。

后续查询仍逐字节读取原录制并核对完整 BLAKE3 身份，再读取索引页。它消除了重复协议解码，不是完全不读取原文件，也不是所有查询都与文件大小无关。普通小文件即使已有内存数据，也绑定实际文件路径；两种时间窗查询都重新读取该文件并验证打开时的身份。原文件同大小内容变更也会拒绝；需要重新打开录制，重建索引不能绕过来源身份检查。没有文件路径的纯内存输入及非 Windows 平台继续使用流式窗口查询。目录、曲线和阶段的已加载内存语义不由时间窗路径绑定改变。

索引保存完整 CPU span、线程、Context、原始 tick 端点、刷新帧和完成到达顺序。查询使用闭区间相交，保留跨窗长事件的完整端点；全源 pending/unmatched/CUDA 计数不改为窗口内计数。相关事件名称有歧义时拒绝结果，未完成事件和 CUDA 缓冲不会被伪造成完成 CPU span。

## 目录和边界

缓存位于当前工作目录的 `pvd-cache/profile`。整个根目录最多使用 1 GiB，包括当前索引、退休查询仍持有的索引、可计量但不能回收的残留和控制文件；它与 TCP 的临时录制、热历史、接收积压和永久 raw 录制分别计量。已有根锁下先回收确认归属的遗留，再申请新额度。首次创建永久控制锁只需 39 字节，允许在低于保留空间时写入，以便后续回收；其他新增内容和覆盖头都先检查至少保留 512 MiB 可用空间。无法获得可用空间时明确拒绝写入。

核心工作内存计量默认 64 MiB，排序 run 默认 8 MiB；外部归并限制扇出和单页行数，不保留全部页表。查询最多返回 200,000 个 span、32 MiB 索引计量，超限明确报错，没有静默截断。容器节点采用估算，SDK 解码器及桌面派生 Analysis/Layout 有各自开销，这些数值不是整个进程的 RSS 上限。

同一根目录只允许一个持有租约的索引所有者。关闭或重建立即使旧槽失效，旧查询仍可在后台完成取消和资源释放；下一建库等待旧租约释放，不另开一个独立 1 GiB 额度。Ready 索引占用一个受限后台清理任务和轻量等待线程。任务在索引发布前注册，失败不会发布 Ready；界面不执行磁盘删除，退出等待查询及清理任务全部完成。

缓存中的永久 `.pvd-studio-profile-lock` 保留，因此正常关闭验收为零索引数据文件，而非整个目录零文件。确认归属的会话、文件名和签名通过预检后，Windows 清理通过同一已验证句柄删除；失败不会退回按路径删除。未知文件、短头或不能可靠计量的目录保留，必要时拒绝新建。父路径必须保持可信；这不是防御任意父目录恶意替换的沙箱。崩溃时半写内容不保证全部自动回收，也不提供索引跨进程重开。

## 使用和验证

载入窗口时分别显示建立索引、整理索引、核验源文件和读取时间窗。整理阶段仅显示忙碌状态，避免把单个归并批次的比例误当总进度。查询失败后可缩窗、过滤或显式重建；取消不会发布部分结果。

“时间窗…”设置可预选“直接扫描（不建索引）”，索引查询错误行也提供“直接扫描”按钮，以同一范围重试。这条路径不获取缓存租约、不建立索引、不等待其他索引所有者，每次完整扫描文件，并保留源身份检查、取消和相同窗口上限。它能用于索引额度不足等情况，不能绕过源变更、数据损坏或窗口超限。切换方式取消旧窗口任务并清空结果，保留线程目录；换源后恢复默认索引方式。已有 Ready 索引仍由原所有者在关闭或重建时回收，切换方式本身不删除它。

索引需与完整文件流式结果比较，覆盖早/中/晚窗口、外部排序、归并、取消、边界和清理。桌面还需从实际文件打开路径核对源绑定、缓存命中后不重复协议解码以及关闭后的索引释放。它不代表所有 SDK 或完整显示性能已验收。
