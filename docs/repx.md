# RepX 导出：已验证范围

`pvd_core::repx::export` 从指定帧的真实对象状态生成 PhysX 3.4.2 RepX XML，支持当前帧的全部受支持刚体及六类官方扩展关节，或指定无关节依赖的 Actor，并收集其 Shape、Material、TriangleMesh、ConvexMesh 和 HeightField 依赖。共享的 Material 和网格资源只写一次。生成完整 XML 后调用者才创建输出文件，缺少依赖或遇到不支持的数据时不会留下貌似成功的文件。

这是一项有明确边界的导出功能，不代表PVD3 的所有 RepX 行为都已复刻。它也不参与录制回放或重新模拟录制。

## 格式依据

使用固定官方 PhysX 3.4.2 commit `5e42a5f112351a223c19c17bb331e6c55037b8eb`：

- `PhysX_3.4/Include/extensions/PxSerialization.h` 定义 collection 依赖闭包、XML serializer/importer 与 tolerance scale 参数。
- `Source/PhysXExtensions/src/serialization/Xml/SnRepXCoreSerializer.cpp` 及相关 metadata 定义刚体/Shape/Material XML 行为。
- `SnJointRepXSerializer.cpp` 的 `PxJointRepXSerializer::fileToObject` 在读取 `Actors/actor0,actor1` 后通过六类专用 factory 创建关节及内部 Constraint；`PxExtensionAutoGeneratedMetaDataObjects.cpp` 定义局部姿态、质量比例和限制参数，`ExtPvd.cpp` 定义 Actor/Joints 与 Parent 的关系。
- `PxSphericalJoint.h` 的 `eLIMIT_ENABLED` 是 bit 1（值 2）；`NpConstraint.cpp::setFlags` 禁止设置只读 `eBROKEN` 与内部 `eGPU_COMPATIBLE`，不能用空洞未知位代替标志。
- 本地手册 p7 明确 Actor 与当前帧 RepX 导出入口。
- 生产器使用真正的 `PxSerialization::serializeCollectionToXml` 生成 `captures/repx-reference.xml`。该文件是 SDK 参考输出，不是 Rust 导出器生成的自定义 schema。

参考根节点为 `PhysX30Collection version="3.4.2"`；Transform 按 quaternion x/y/z/w 后 position x/y/z 序列化。exclusive Shape 几何嵌套在 Actor 的 `Shapes/PxShape/Geometry` 下，共享 Shape 独立写入顶层并由 Actor 的 `Shapes/PxShapeRef` 引用，Material 用 ID 引用。XML 的名字由验证过的 SDK 类型决定，用户字符串按 XML 规则转义。

## 当前支持与明确拒绝

支持 `PxRigidStatic` / `PxRigidDynamic`、exclusive Shape 的 plane/box/sphere/capsule、TriangleMesh、ConvexMesh、HeightField 几何和 Material；复制全局/局部位姿、质量/惯量、速度/阻尼、阈值、求解迭代、过滤数据、已知 flags 和材质参数。包含 SDK tolerance scale。对象引用检查当前代际，不能把已销毁对象的指针误接到复用 ID 的新对象。

网格和地形保留各自资源 ID，单独序列化资源，再由 Shape 引用；支持多个 Actor 的不同 exclusive Shape 引用同一资源。TriangleMesh 保留捕获顶点、三角索引、逐三角材质表，Shape 保留带旋转的非均匀/负缩放和 `eDOUBLE_SIDED`。ConvexMesh 保留捕获顶点、正缩放、最大 margin 和 `eTIGHT_BOUNDS`，检查捕获的面/索引构成闭合、一致朝向的凸体。HeightField 保留行列、格式、厚度、凸边阈值、flags、带符号高度和两个完整材质字节，包括洞、细分方向和边标记；Shape 保留三个比例、flags、材料表和局部位姿。

整帧支持 `PxSphericalJoint` 的 world/dynamic、dynamic/dynamic、static/dynamic 连接。Actor 与 Joint 双向引用及 Parent 必须一致且代际有效，先输出 Actor 再输出关节；保留两个局部姿态、break force/torque、四个 inverse mass/inertia scale、ConstraintFlags、名字、完整 LimitCone、SphericalJointFlags 和 ProjectionLinearTolerance。RelativeTransform/RelativeLinearVelocity/RelativeAngularVelocity 是只读派生观测，检查数值类型与有效性，不作为可写参数输出。SDK importer 自动建立内部 Constraint，导出器不会伪造一个独立 Constraint。

同一依赖闭包也支持以下五类 PhysX 3.4.2 官方扩展关节，字段完整性逐类检查，缺失字段不会退回默认值：

| 类型 | 除公共 Joint 字段外保留的可写属性 |
| --- | --- |
| `PxFixedJoint` | 线性、角投影容差 |
| `PxDistanceJoint` | 最小/最大距离、容差、刚度、阻尼、三个距离/弹簧 flag |
| `PxRevoluteJoint` | 完整角度 Limit、驱动速度/力上限/齿轮比、三个 limit/drive flag、两个投影容差 |
| `PxPrismaticJoint` | 完整线性 Limit、limit flag、两个投影容差 |
| `PxD6Joint` | 六轴 Motion；完整 LinearLimit/TwistLimit/SwingLimit；六个 Drive 的刚度/阻尼/力上限/acceleration flag；驱动目标姿态、线性/角速度；两个投影容差 |

公共字段包括 Actor/Parent 依赖、两个局部姿态、break force/torque、四个 inverse mass/inertia scale、可恢复 ConstraintFlags 及名字。Distance/Position/Angle/Velocity/Twist/SwingYAngle/SwingZAngle 等派生读数检查类型及有限性，但不当作可写参数。D6 使用 SDK 的轴/驱动枚举名称，不能交换 `eSWING` Drive 与 `eSWING1/eSWING2` Motion；零 flag 仍恢复为零。

数值边界取自固定 SDK 的 setter、`PxJointLimitParameters::isValid` 与各 limit/drive 类型。角投影容差为 `[0, pi]`，锥角为 `(0, pi)`；Revolute 上下界严格位于 `(-pi, pi)`，D6 twist 上下界严格位于 `(-2pi, 2pi)` 且跨度小于 `2pi`。线性/角度区间要求 lower≤upper，contactDistance 不超过跨度，线性跨度不得溢出。D6 线性上限必须大于零，Drive 参数不得负数且只接受 acceleration bit 0。Distance 各参数要求非负且 min≤max；Revolute 齿轮比必须大于零，驱动力上限不得负数。未知枚举/flag、缺失 Drive 项、非法姿态或坏数值均明确拒绝。


以下情况明确报错：

- 不是已验证的 PhysX 3.4.2；不存在 Actor、缺失属性、失效引用、未知字段/flag、非有限数或非法 XML 控制字符。
- 属性数据类型错误、几何尺寸非法、四元数未归一化、Shape 所属 Actor 不一致、过滤数据不是四个 u32，或质量/惯量/材质/接触偏移等数值违反 SDK 约束。
- 六类官方扩展之外的 Joint、独立 Constraint、Aggregate、Articulation、Cloth、Particle 等尚无导出实现的对象。
- 单 Actor 带有 Joint 依赖；两个关节端点相同/都为空/没有 dynamic Actor、Actor/Joints/Parent 关系不一致；已断裂、内部 GPU 或未知 ConstraintFlags，非法 LimitCone 或质量比例。
- 网格索引越界/重复、退化三角形、开放/非凸/非平面 hull、无效缩放、缺少必要材质表、越界材质索引、HeightField 尺寸/采样数不一致或非法 i16 高度、未知 geometry flags。
- 超过 1,000,000 网格顶点、3,000,000 三角索引、255 个凸顶点/面、1,000,000 地形采样，以及保守估计超过 128 MiB 的资源 XML。
- 运动学刚体所需的 kinematic target 未由导出器完整保存；非零 client behavior flags 未验证。

当前帧有不支持的对象时不静默丢弃它们。选择不依赖该对象的单个受支持 Actor 仍可导出。单 Actor 的关节依赖闭包可能引入其他 Actor，当前没有采用未经对照的隐式扩张语义，因此明确拒绝连接了 Joint 的单 Actor。共享 Shape 的独立对象、附着关系、代际与选中闭包已通过五帧真实 SDK 验证，详见 [共享 Shape](repx-shared-shapes.md)。

RepX collection 本身不序列化完整 `PxScene`，本实现没有宣称保存场景 gravity、filter shader、回调、运行时睡眠状态或所有求解器内部状态。UpVector 使用 SDK 默认未指定值 `0 0 0`；消费者负责建立场景。当前帧导出表示受支持对象的快照，不是完整可重复模拟的保证。

### Portable mesh 资源与内部 cooking 数据

官方 `SnRepXCoreSerializer.cpp` 在未提供 cooker 时以顶点/索引输出网格 XML，在导入时由 SDK cooker 创建资源。ConvexMesh 的官方 portable XML 只写 `points`，导入器通过 `eCOMPUTE_CONVEX` 重建 hull。PVD 不发送 cooked BVH 或 convex hull 的原始面方程；本实现按官方 portable XML 路径导出，先用已有 HullPolygons/PolygonIndexes 校验几何有效性。此处 cooker 仅建立 RepX 资源，没有模拟录制或替代展示数据。

TriangleMesh 的 PVD 资源类型是基础 `PxTriangleMesh`，没有 BVH33/BVH34、GPU cooking 参数或原始 cooker 配置。本实现明确使用 `PxBVH33TriangleMesh` portable 资源，不声称恢复原始加速结构。SDK 可以在 cooking 中调整顶点/面顺序；已验证样例的原始顶点/索引、凸体质量/惯量均保持一致，不能推广为任意网格的 bitwise cooked 数据一致。

HeightField XML 的 `samples` 使用官方 `writeHeightFieldSample` 的可移植 u32 表达：低 16 位是有符号高度的位模式，高 16 位依次保存两个原始材质字节。采样缓存的内部布局不会被当成可随意解释的用户数据。

## 可重复的 SDK 互验

先构建 CLI 与 [SDK 生产器](../tools/physx-sample/README.md)，并生成 baseline/rich 样例，然后运行：

```powershell
cargo build --locked -p pvd-cli
python tools/physx-sample/verify-repx.py --cli target/debug/pvd-cli.exe --producer .deps/physx-sample-build/Release/pvd-physx-sample.exe --capture captures/physx-3.4.pvdstream --rich-capture captures/physx-3.4-rich.pvdstream
```

互验过程：Rust 从录制生成 XML → 官方 SDK `createCollectionFromXml` 重建对象 → 官方 SDK 再次导出 XML → 比较所有输入叶属性以及 Actor/Shape/Material 数量。使用 `1e-5` 的相对/绝对数值容差，因为官方 XML serializer 使用有限有效位数。SDK 对值为零的 flags 的正常省略单独处理，其他字段丢失或意外默认值均失败。

实际通过：

| 验证 | 结果 |
| --- | --- |
| baseline 帧 0、60、90、119 | 每次 SDK 导入 3 Actor、3 Shape、1 Material，89 个有值叶属性一致 |
| 帧 60 选中已改名的 Box | SDK 导入 1 Actor、1 Shape、1 Material，42 个叶属性一致 |
| baseline 属性互验 | 398 个；包括销毁/ID 复用之后的快照 |
| rich 整帧 | SDK 导入 6 Actor、6 Shape、1 Material、1 球形关节；21 个关节叶属性一致，合计 419 个属性 |
| rich 连接关节的单 Actor | 明确拒绝，不创建输出文件 |
| 不存在 Actor | 明确报错，不创建输出文件 |
| XML 转义/非法控制字符/非有限数 | 核心自动化测试通过 |
| 对真实录制帧进行属性变异 | 缺失质量、NaN/负尺寸、错误数据类型、Infinity/负质量、零四元数、未知 flags 及超出 u32 的过滤数据均被拒绝 |

录制变异测试通过 `cargo test -p pvd-core --lib repx::tests -- --include-ignored` 显式运行，依赖 baseline 输入。其他帧、flags、SDK 和原版行为需分别验证。

### TriangleMesh / ConvexMesh / HeightField 独立互验

```powershell
.\tools\repx-meshes\build.ps1
cargo build --locked -p pvd-cli
python tools/repx-meshes/verify.py
```

这个生产器与读取器通过现有 PhysX 3.4.2 SDK 编译，不修改 SDK 或使用自行编写的 XML 读取器。它创建六个真实 Actor、六个 exclusive Shape、两个 Material、一个 TriangleMesh、一个 ConvexMesh、一个 HeightField；每个资源分别被两个 Shape 共享。SDK 同时输出 PVD 捕获、自己的参考 RepX 和通过 getter/`PxMeshQuery` 获得的 JSON 真值。随后验证整帧及六个 Actor 的 Rust 导出，使用官方 `createCollectionFromXml` 重读并比较：

- 捕获中的原始顶点、每条面索引、凸体质量/中心/惯量。
- HeightField 完整采样、洞、细分、SDK 生成的可见三角形、厚度、flags 和凸边阈值。
- 顺序敏感的材质表、逐三角材质索引、对象位姿、Shape 位姿、负/旋转缩放、geometry flags、margin。
- 资源 ID，以及共享资源只输出一次；对象 ID 和整型值必须完全一致。

网格和地形需由官方 importer 重读，核对资源、缩放、Actor 和 Shape。primitive、mesh 和 joint 专项各自验证对应范围。

固定路径录制为 206,283 字节，SHA-256 `acd9eebf85f19906fe270b6b360a396a92c8a3d6d20eca1509f627c54aeaf4e5`。录制含真实进程地址与计时，不要求再次生成同一哈希。

生成固定路径输入并运行损坏边界测试：

```powershell
.\.deps\physx-repx-meshes-build\Release\pvd-repx-meshes.exe captures/physx-3.4-repx-meshes.pvdstream captures/physx-3.4-repx-meshes.reference.xml captures/physx-3.4-repx-meshes.meshes.json
cargo test --locked -p pvd-core --test repx_meshes -- --include-ignored
```

可通过 `PVD_REPX_MESH_CAPTURE` 指定对应捕获。该测试明确是需要真实 SDK 数据的 ignored 测试，覆盖共享资源去重、错误索引/材质表、无效数值/flags、失效资源代际、开放凸 hull 和非法地形采样；缺少真实输入时不能把它记作已通过。本组网格测试不覆盖原始 cooked 数据、Articulation、自定义 Joint、shared Shape 或其他 SDK 版本的扩展；共享基础 Shape 有单独的生产器与验证记录。

### PxSphericalJoint 独立 getter 互验

```powershell
.\tools\repx-joints\build.ps1
cargo build --locked -p pvd-cli
python tools/repx-joints/verify.py --cli target/debug/pvd-cli.exe --rich-producer .deps/physx-sample-build/Release/pvd-physx-sample.exe
```

球形关节生产器以 Debug 编译，并链接已经构建的固定 SDK checked 库。它创建四个 Actor、三个球形关节；在三个帧中改变局部旋转/位置、名字、质量比例、limits、flags，然后销毁一个关节。SDK 在各帧 simulate 前直接读取 getter 真值并生成自己的参考 XML，与 PVD 的帧状态边界一致。验证脚本先检查官方 XML 自身导入，再比较 Rust XML 导入后的 getter：包括内部 Constraint 的 Actor 引用和关节 Actor 引用一致，ID 精确相等，浮点相对容差 `1e-5`、绝对容差 `1e-6`。

指定 `--rich-producer` 时还生成一个独立 rich 捕获和官方参考 XML，分别将官方 XML 与 Rust XML 导入 SDK 后比较 getter。原 sample 的 reference collection 使用序号 ID；PVD 使用指针 ID，因此仅这条 rich 对照按唯一 Actor 名称匹配连接身份，不把不同编号当成对象不同。

Windows 11、MSVC 19.50、x64 实际结果：

| 验证 | 结果 |
| --- | --- |
| 三帧 SDK 直接 getter → 官方 XML 导入 getter | 408 个值一致 |
| 三帧 SDK 直接 getter → Rust XML 导入 getter | 408 个值一致，关节数量 3、3、2 |
| rich 全帧，独立官方 XML 对照 Rust XML | 89 个 Actor/Joint getter 值一致，保留 1 个球形关节 |
| 连接 Joint 的单 Actor | 明确报错，未创建输出文件 |
| 真实已有 rich 帧 0、60、119 | 核心导出保留球形关节；不相关 Box 可单独导出 |
| 原始/变异真实捕获 | 两项 ignored 集成测试显式通过，含失效 Actor/Joint 代际、缺少/错误引用、孤立反向关系、未知字段、坏数值、不可恢复 flags、其他 Joint 与独立 Constraint |
| 常规数值/标志边界 | 不依赖录制的单元测试验证稀疏 flags、球形限制 bit 1 和 SDK 数值边界 |

固定入口使用 `captures/physx-3.4-repx-joints.pvdstream`，同 stem 的三个 `.frame-N.json` 为 SDK getter 真值。其他 flags、类型、SDK 和原版行为需单独验证。

每次验证生成唯一输出目录。将下面路径替换为该次验证输出路径后显式运行：

### Fixed / Distance / Revolute / Prismatic / D6 互验

```powershell
.\tools\repx-joints\build.ps1
cargo build --locked -p pvd-cli
python tools/repx-joints/verify.py --expanded --rich-producer .deps/physx-sample-build/Release/pvd-physx-sample.exe
cargo test --locked -p pvd-core --test repx_joints -- --include-ignored
cargo test --locked -p pvd-core --lib repx::tests -- --include-ignored
```

`--expanded` 保留三个球形关节，并分别创建一个 Fixed、Distance、Revolute、Prismatic、D6。它包含 world/dynamic、dynamic/dynamic、static/dynamic 连接；五类各自配置非默认参数，并在第二帧改变局部姿态、投影/limits/drive/flags，第三帧销毁五个扩展关节及一个球形关节。D6 六个 Motion 同时覆盖 locked/limited/free，六个 Drive 覆盖 force/acceleration 模式；第二帧 twist 的 `[3.3, 4.7]` 区间特意超过 Revolute 的 pi 上界，仍满足 D6 setter 的约束。

生产器在每一帧模拟前通过 getter 保存直接 JSON 真值，独立生成官方 XML；验证先确保官方 XML 导入后 getter 与直接值一致，再从同帧 PVD 捕获执行 Rust 导出并比较官方 SDK 导入后的 getter。所有值都来自 SDK；验证不使用 Rust XML 自己解析出的值作为预期值。独立 Constraint 的 Actor getter 也与 Joint 的 Actor getter 比较。模板循环没有把五类映射成同一类型或省略其专用字段。

Windows 11、MSVC x64、Debug 生产器及 checked PhysX SDK 实测：

| 检查 | 结果 |
| --- | --- |
| 三帧顺序与随机状态验证 | 3 帧通过；关节数为 8、8、2 |
| SDK 直接 getter → 官方 XML 导入 getter | 888 个值一致 |
| SDK 直接 getter → Rust XML 导入 getter | 888 个值一致，完整保留六类关节身份和专用参数 |
| rich 官方 XML 对照 Rust XML | 90 个 Actor/Joint getter 值一致（包含 Joint 类型身份） |
| 五类变异数据 | 缺少任意已捕获字段、坏数值/类型/flags、失效 Actor 或 Joint 代际、未知对象字段、非法 XML 字符均拒绝 |
| 限制边界 | contactDistance 超跨度、上下界倒置、跨度浮点溢出、非法 D6 Motion/DriveFlags/姿态/速度、Revolute pi 边界均拒绝 |
| 单 Actor 带有关节依赖 | 仍明确拒绝，未隐式扩张或丢失关节 |

扩大范围专项使用 `PVD_REPX_EXPANDED_JOINT_CAPTURE`，配套同 stem 的三个 `.frame-N.json`。球形专项使用 `PVD_REPX_JOINT_CAPTURE`。重录时指针和计时会变化，应比较同次真值。

这一验证覆盖五类各一个配置和一次属性更新，不代表所有参数排列、全类型端点排列、关节断裂状态、用户自定义关节、其他 SDK 或 PVD3 自身 RepX UI 行为已经通过。

直接使用：

```powershell
pvd-cli repx captures/physx-3.4.pvdstream 60 output/frame60.xml
pvd-cli repx captures/physx-3.4.pvdstream 60 output/actor.xml 0xACTOR_ID
```

将 `0xACTOR_ID` 替换为该帧中真实 Actor ID；输出路径必须不存在。
