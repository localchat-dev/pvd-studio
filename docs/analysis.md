# 性能与内存分析证据

实现位于 `crates/pvd-core/src/analysis.rs`，不依赖桌面。源定义来自固定 PhysX 3.4 SDK 提交 `5e42a5f112351a223c19c17bb331e6c55037b8eb`。

## 性能缓冲区

`PxShared/src/pvd/src/PxProfileEvents.h`、`PxProfileEventSerialization.h`、`PxProfileEventParser.h` 定义：事件种类 u8、压缩选项 u8、事件 ID u16，后接上下文、线程和绝对/差分计数器时间。每个缓冲区重置压缩上下文；尚未结束的区间保留到后续缓冲区。按照 zone/event/thread/context 配对，保留嵌套开始栈；不能跨不同事件名拼出完整区间。

`PxPvdProfileZoneClient.cpp` 把缓冲区作为 profile zone 的 `events` 属性输出。区间时间以流头的计数器分数换算。`PxPvdCommStreamEvents.h` 的分子乘 10 已将 foundation 的十纳秒换算转为纳秒，不再次乘 10。标量值没有自身时间戳，保留原始整数而不伪造时间点。

当前支持完整 CPU 开始/结束、相对开始/结束和标量值结构。SDK 早期 CUDA 缓冲区按已知结构边界保留计数，未提供 GPU 内容分析。未知事件没有可靠长度时停止并报告嵌入缓冲区偏移。

## 内存缓冲区

`PxProfileMemoryEvents.h` 的 u16 头部携带类型与五个压缩宽度。解析字符串表、分配和释放；32 位字段即使使用 U64 压缩标志仍按 SDK 序列化器的 32 位分支读取。内存表按源对象和地址隔离，报告存活字节、峰值、累计分配、释放、未知释放与重复地址。

SDK 内存事件本身没有逐次分配的时间戳。曲线横轴使用缓冲区送达时的帧索引，不能声称事件发生在该帧某个精确时刻。缺失前置捕获引起的未知释放不会伪造负数内存，也不会归入已知分配。

## 实际观察

真实 SDK 捕获可能保留未闭合区间或未配对结束事件。分析会显示这些缺口，不能用补造时间使其成为完整区间。

静态源码能看到 `ScScene.cpp` 中多处同名开始/结束调用，但仅凭此不能把所有缺口判为 SDK 缺陷。消费者不通过改事件名或猜结束时间修补。完整区间数会随 SDK 执行、线程安排和场景变化，不作为跨运行固定常量。

上述记录证明这些样例的缓冲区可解析、导出与展示，不等于所有事件/线程/GPU/SDK 均验证，也不等于与原版分析面板逐项比对通过。
