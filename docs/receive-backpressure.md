# TCP 接收与缓存

PhysX 3.4 的默认 socket transport 使用阻塞写入，帧结束时同步发送 PVD 数据。接收方长期处理不过来时，反压可能延伸到源端物理调用。独立磁盘缓冲把 socket 读取与解码分开，但不能替代足够的处理吞吐。

## 空连接、协议头与断开

TCP 建立后先显示“已连接 · 等待 PVD 数据”，收到首批非空数据后才显示“接收中”并创建可选原始录制。会话在没有收到任何字节且没有其他故障时结束，提示“未收到数据便已断开”，不生成录制、不调用流结束解析，也不停止监听；主动停止空会话同样不报告协议截断。

收到部分协议头后断开仍属于不完整捕获，会保留截断错误和已收到的原始前缀。完整协议头但没有帧属于合法的零帧流，与零字节连接分别处理。正常断开时还会核对传输层与解码线程的字节总数，计数不一致按故障报告，避免把未交付的数据误判为空连接。文件解析仍拒绝空文件。

## 接收与容量策略

- 桌面使用独立 socket 线程将数据按顺序写入短期磁盘接收缓冲。另一个线程交付解析器；解析、历史写盘和 UI 消费不会直接阻止 socket 读取。
- 接收缓冲分段 **16 MiB**，默认 **0 GiB（不设固定配额）**，受可用磁盘空间和保留空间约束。可在“录制设置”中指定正数 GiB 配额，监听期间不可修改。它位于历史目录下的 `receive` 独立子目录，独立于热历史、完整临时录制和永久录制。已交给解析器的完整分段释放；尚未释放的分段前缀仍计入占用和显式配额。
- 仍保留最多 32 块、每块最多 64 KiB 的交付内存队列及当前解析块。界面的“磁盘接收积压”不包括这些字节，也不是以秒表示的画面延迟。
- 磁盘积压达到 **256 MiB** 时显示黄色“积压较大，继续接收”，不因此断开，不切换跟随/暂停状态，也不丢弃协议事件。
- 达到显式接收配额、写盘失败或无法满足保留空间时，仍结束这条 SDK 调试会话并报告故障。保留空间默认且最低 **512 MiB**，可在“录制设置”中提高，并同时用于接收和历史。已保存的连续前缀按序交付，捕获标为失败/不完整；不丢掉中间事件后继续伪装完整连接。
- 正常断开后仍可处理已经接收的数据；界面区分 TCP 接收状态和解码状态。用户停止监听会直接关闭 socket，无需等待当前解码工作完成。
- 用户主动停止或关闭录制先停止 socket 接收，再按序交付已提交的接收缓冲，最后发布结束事件。结束在协议包中途时仍报告截断，只保留可恢复的完整帧。应用退出或后台任务被强制取消使用独立取消路径，可释放未交付缓冲；永久 `.partial` 此时仅含已交给解析线程的连续前缀。永久保存与接收缓冲尚未合并为同一份可恢复日志。

独立缓冲吸收积压，但不设固定配额仍不代表无限容量。若持续输入超过处理能力，磁盘占用和显示延迟会增长；达到显式配额或真实磁盘边界时仍需排查积压并重新连接。磁盘 I/O、SDK 序列化、网络与 CPU 仍有成本，不能保证调试连接对游戏完全没有影响。

磁盘提交的字节、完成标记与条件变量谓词由同一把锁保护。交付队列在消费、取消或消费者退出时唤醒，详见[交付与历史取消](delivery-and-replay-latency.md)。accept、socket 和状态通知仍有独立等待。

## 显示与诊断

界面分别显示 TCP 字节、接收积压和缓存占用。跟随实时表示最新已解码帧，不能保证等同于源端此刻的帧；画面更新计数也不等于 GPU 帧率。SDK 自身可能批量发送，小流不保证逐帧到达。

暂停与回放不停止接收。需要判断瓶颈时，分别记录源端、接收、解码、历史提交和显示进度，见[实时吞吐](realtime-throughput.md)及[诊断工具](../tools/README-live-probe.md)。空连接无法说明发送端没有发送数据的原因。

原版也为对象历史创建磁盘文件，但其线程结构、缓存和容量策略不能仅从此推断，见[原版对照](live-history-memory.md)。本项目区分接收缓存、当前状态、[完整临时录制](temporary-recordings.md)、热回放缓存、永久录制和显示缓存。

## 活动数量的口径

界面分别显示 SDK 活动动态、SDK 活动运动学及其合计。数据来自 `PxScene::getSimulationStatistics()`，由 PVD metadata binding 作为 `SimulationStatistics.NbActiveDynamicBodies` / `SimulationStatistics.NbActiveKinematicBodies` 属性发送。PhysX 3.4 的 `PxSimulationStatistics.h` 明确前者不含活动运动学刚体；运动学统计仍包含该帧末刚停用的刚体。

另列的未休眠动态、休眠动态、运动学、静态和未知类别按唯一 Actor ID 计数，互斥且合计为刚体总数；对象范围为 `PxRigidStatic`、`PxRigidDynamic`、`PxArticulationLink`，不混入粒子或布料。分类不受视口过滤和 Shape 数量影响。缺失或无效的必要字段计为未知；经典 Articulation Link 根据有效代际引用找到所属 `PxArticulation`，继承其睡眠状态，不能从单个 Link 的字段猜测。PhysX 3.4 不允许 Link 为运动学刚体；其他尚未识别的 owner 类型，包括未验证的 ReducedCoordinate owner，保守归为未知。

`IsSleeping=false` 不等于 SDK 活动数量。真实基础捕获的第 77、103 帧只有一个未休眠动态 Actor，但 SDK 活动动态统计为两个；下一帧才变为一个。CCT 样例第 1 帧报告活动动态 0、活动运动学 2。两项都作为真实捕获回归断言，不以未休眠数填补缺失的 SDK 统计。原版是否在某个固定位置展示这些数值尚未做逐控件对照。

计数属于当前显示状态，暂停和回放时跟随显示帧，返回实时后重新对应最新解码状态。多个 `PxScene` 的 SDK 合计只在每个 Scene 均具有有效对应字段时显示，任一 Scene 缺失则该项总数未知；动态和运动学分别检查完整性。多 Scene 聚合使用当前显示状态中各 Scene 最近捕获的统计，不能据此声称独立异步 Scene 在同一个物理时刻有该数量。

首次加载、跳帧和返回实时允许全量重建计数。后续仅使用 `SceneUpdate.changed_objects()` 中的对象及受父链变化影响的 Articulation Links 更新缓存，不在每次绘制 UI 时扫描所有对象。普通 Actor 直接使用 patch 对象；父链依赖索引处理 owner 睡眠、销毁、ID 复用和引用变更。

## 验证

回归覆盖空连接、首字节前停止、残缺协议头、合法零帧流、完整数据、重连隔离、显式配额、空间保护、告警、顺序排空和退出清理。真实 SDK 分片/截断及持续负载需另行生成输入并执行。

活动统计使用 [baseline](../tools/physx-sample/README.md) 与 [CCT](cct-live-history-fixture.md) 配对输入：

```powershell
cargo test --locked -p pvd-desktop activity::tests
cargo test --locked --release -p pvd-desktop activity::tests -- --ignored --nocapture --test-threads=1
```

第二条包含真实输入和微测量，需先准备 `captures/physx-3.4.pvdstream`、`captures/physx-3.4-cct.pvdstream`。计数微测量不包含接收、解析、历史或 GPU，不能换算为完整帧率。
