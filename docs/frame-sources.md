# 帧来源与回放

SDK 捕获按 `frame` 和 `ApexFrame` 的实际结束事件建立帧。来源由原始 source ID 和名称共同标识，同一 ID 的两种名称仍是两个来源。未结束的数据不补成一帧，也不根据指针关系或时间戳推断 APEX 所属的 PhysX Scene。

## 选择来源

有多个来源时，工具栏显示帧源选择器。帧号、逐帧、首尾定位、正倒放和时间轴跟随所选来源。默认优先最早出现的 PhysX 来源；没有 PhysX 时使用最早出现的来源。滚动淘汰不会自动切换来源。

暂停时切换来源，定位到当前捕获位置之前最近的对应帧；没有更早帧时使用该来源的首个保留帧。实时切换会等待所选来源的下一个完整帧，期间保留当前画面并显示等待状态。各来源的 ticks 不用于跨来源对齐。

选择帧源决定回放边界，Scene 过滤决定显示对象，两者独立。其他 Scene 的对象仍是该捕获位置最近收到的状态，不代表所有 Scene 处于同一物理时刻。阶段曲线只使用具有实际 Scene 关联的 PhysX 帧。

## 两种帧号

| 入口 | 帧号 |
| --- | --- |
| 工具栏、时间轴和逐帧播放 | 所选来源内的序号 |
| CLI、分析跳帧、片段列表和 SDK 裁剪 | 所有已知结束事件按捕获顺序编号的全局索引 |

分析跳帧会切换到目标帧的来源。滚动淘汰或历史写入失败可以留下序号缺口；导航只使用仍可读取的帧，不压缩剩余序号。

`Recording::seconds_at`、CLI `seconds` 与属性 CSV 的 `time_seconds` 以当前来源首个可见帧为零点；`Legacy` 轴使用录制首个可见帧。隐藏恢复前缀不参与计时，各来源的经过时间不能拼成共同时间轴。属性 CSV 保留全局 `frame`，并在原有列末附加 `section`、`source_id`、`source_frame` 以识别来源。

时间戳早于该来源的可见起点时，CLI 显示 `unavailable`，CSV 时间留空并保留属性行。来源目录缺失或与帧不匹配时，CSV 明确拒绝导出，不补造来源或序号。

[项目捕获](retained-capture.md)保留全局索引、来源键和来源内序号，保存范围包含其中的全部来源。旧 `PVDCAP01/02` 与原版数据库导入使用“录制帧”（`Legacy`）轴，不补造缺失的 SDK 来源。SDK 裁剪输出从保留的完整 End 重新编号，规则见[片段](clips.md)。

## 绘制窗口

每个来源的一帧使用前一个同源 End 之后、当前 End 之前收到的 renderer 绘制；该来源首帧从捕获起点开始。另一个来源的 End 不会清除这段绘制。分块属性在完整提交时生效，实例状态继续跨 renderer 缓冲保留。

APEX 异步获取结果可能在 PhysX 与 APEX 的 End 之后发送绘制。这些数据保持实际发送位置，只能进入后续真实边界；文件末尾的未提交绘制不会回填到已结束的帧。显示分析也使用当前完成边界，不用录制尾部分析替代当前帧。

TCP、磁盘解码和流式裁剪的绘制日志上限为 64 MiB，同时受核心剩余内存预算限制。长期不再产生 End 的来源可能阻止回收；超限或新来源需要已经回收的起始历史时明确失败，不静默删减绘制。此额度不代表磁盘历史大小或进程总内存上限。

APEX 1.4 CPU Clothing 的输入生成和独立 getter 核对见[生产器说明](../tools/physx-apex-clothing/README.md)。实现与验收范围见[兼容矩阵](compatibility.md)及[验证说明](validation.md)。
