# TCP 历史播放、过期帧与缓存目录

## 过期画面的播放边界

暂停只保留画面，接收和历史追加继续。滚动淘汰后显示帧可能早于可读历史下界，回放入口必须先把目标定位到可用范围。

播放入口统一处理范围：从已过期画面正放时定位到保留首帧，倒放时定位到保留末帧。离线末帧重新播放从保留首帧开始，保留首帧点击倒放从末帧开始。暂停在实时末端点击播放恢复跟随，正放追到仍连接的实时末端也恢复跟随。连续播放到已断开的末端或倒放到首端仍停止。取消倒放使用与暂停一致的在途取消路径。

加载或正放过程中，后台也可能继续淘汰最早历史。首次恢复精确定位保留首帧；若该目标在加载期间再次过期，重试按范围推进速度留出余量，且恢复帧的下一步也必须可用；连续三次过期失败即停止。范围元数据持续缺失两秒或重试耗尽会停止并显示原因，不强制返回实时。其他读取错误仍停止并报错，倒放到保留首端后停止。异步恢复耗时计入播放间隔，不在每次完成后再额外等待整个间隔；首次加载严重落后时仍使用有界追赶，避免长时间密集请求。

帧输入框保留实际显示帧，不因保留范围推进而改写数字或自动触发跳转；提示中给出保留范围。没有可用历史时显示原因，诊断JSON包含历史占用、预算、首帧、帧数、分段数和历史警告。

## 连续磁盘回放

连续播放从首步使用 `seek_scene`，暂停后按面板和曲线需要加载分析。原帧仍可读时精确重试，已过期时显式加载最新可用帧，等待时保留画面。完整分析恢复成本属于显式分析请求，不是每个场景步进必做的工作。

核心的`live::ReplayCursor`不依赖Bevy/egui。同一会话资源仓库内，正向相邻帧跨时间分段直接应用索引与对象赋值增量；最多120帧、8MiB的偏移撤销缓存支持相邻反向移动，只恢复涉及的对象、绘制、接触和代际。未命中缓存或随机定位才恢复目标偏移索引，再仅读取偏移不同的记录。反向恢复同时移除较晚创建对象的代际条目，避免未来生命周期污染较早帧。

写入器、直接读取与回放游标共享一份分析缓存，最多32条、按共享结构计量192MiB；近期回放恢复点超过6份时优先淘汰较旧者，6不是硬条数限制。正向应用新增分析输入，反向从合适的恢复点重放。当前分析、显示快照和实时状态另计，不是进程RSS硬上限。保留操作记录裁剪首帧和捕获预算，不推断维护水位。首次冷定位、越出缓存覆盖范围的倒放或分析输入不连续时仍可能完整恢复分析基线。具体缓存准入、冷定位与测量见[分析缓存](analysis-seek-cache.md)，存储所有权见[共享历史存储](shared-history.md)。

常驻分配索引使用共享节点的平衡树，快照复制只增加根节点引用；分配、替换和释放只复制修改路径。已发布快照与反向分析起点保持不可变，避免每帧复制150,000个常驻索引节点。顺序遍历及序列化保持原有有序map的字节布局，节点占用由原有分配索引条目预算覆盖，并有节点尺寸上界测试。性能事件、分配事件列表、首次解码和冷基线恢复仍有各自成本。

后台worker仅以界面已经取走的结果作为下一次显示增量的基准。完成但未发布的请求被替换、取消或换源时清除游标；返回实时和关闭会话也请求后台释放缓存。保留读取取消与generation校验，旧请求不能覆盖显示。单次系统读取、反序列化和分析缓冲处理的不可中断范围仍存在。

性能探针`crates/pvd-core/examples/replay_latency.rs`使用真实SDK捕获，保留上一份显示分析快照以覆盖共享后写入的复制成本。首次定位与连续步进分开记录，结果不包含完整原生窗口或GPU。实际测量及持续TCP证据见[验证说明](validation.md)。

## 场景更新的所有权

磁盘恢复结果独占其读取出的对象时，`SceneUpdate::apply_owned`把对象、属性表和引用绑定直接交给显示状态；仍有共享持有者时复制对象以保持其他读者不变。树与场景变化依赖在消费结果前读取，活动统计在应用后按变化ID更新。跟随实时需要同时维护最新状态和显示状态，因此先借用应用到最新状态，再消费应用到显示状态；暂停时只消费到最新状态，不改变暂停画面。

场景应用测量需区分首次载入、替换完整状态和少量对象增量，并覆盖仍有共享持有者的分支。计时应包含旧状态销毁，独立记录核心恢复、调度和 GPU 成本。

## 文件位置与占盘

默认历史目录为当前工作目录下的`pvd-cache/history`，本项目已经创建该目录；TCP接收缓冲位于其`receive`子目录。发行包包含相同的空目录，诊断启动脚本将工作目录设为解压目录。旧设置若仍等于程序原有默认的`%TEMP%/pvd-studio-live`，读取偏好时迁移到新默认；用户自定义路径保留。现有活动会话仍使用启动时的目录，新程序的新会话使用新设置。

8GiB是滚动历史的默认保留预算，暂停不停止追加；达到预算或空间约束后淘汰最早整段。正常释放会话后清理其临时文件。目录迁移不会把滚动历史变成永久原始录制，也不会恢复已淘汰帧。

内部临时格式`PVDHIS03`把对象版本和大资源从时间分段中分离，并保留逐帧捕获相机。检查点保存版本目录，跨段复用未变化对象；大记录按内容分块复用，分析基线的相同块只落盘一份。时间分段默认最多600帧或64MiB新增内容；到达预算时淘汰旧帧并回收不可达资源，实际占用包括在途读者、整理和删除失败的文件。数据仍包含解析结果、分析输入、目录和校验，不保证小于TCP原始字节；永久原始录制独立。

## 原版PVD3对照

参考 `PVD3.exe` SHA-256为`8a357c845b2622b19ca4c391086de83c9de2e45787d518d972f2490f1c524420`，与[证据登记](evidence.md)一致。`PvdListener::initializePvdServer`将临时随机访问读写文件交给对象历史工厂；已验证的真实容器含事件页、快照目录、实例位置表，以及属性变更的undo引用，见[原版格式](original-file-format.md)。

`objdump` 指令核对`PvdObjectModelEventStreamImpl::seekToEvent`（MAP13902，`0x1400EE930`）：`0x1400EEB72`调用`EventUndoOperator`分派器`0x1400E8F50`，随后递减事件位置；`0x1400EEDD3`调用`EventDoOperator`分派器`0x1400E8B20`。这证明原版定位代码包含向后撤销和向前应用的路径；`0x1F4`比较的是事件位置距离，不能解释为500帧或磁盘配额。

匹配[参考文件身份](evidence.md)的函数体和虚表观察：

| 原版机制 | 函数体证据 | 可确认的边界 |
| --- | --- | --- |
| 跨快照复用实例 | `writeInstance`（MAP13971，`0x1400F4A40`）在`0x1400F4A5A`查`getLastWriteInfo`，命中后在`0x1400F4A66–73`直接返回既有位置；属性更新在`0x1400F432E`使该位置表条目失效 | 未变化实例不因保存快照而重写全部字节；属性变化会产生可重新保存的实例版本。不能外推所有异常修改路径已穷尽。 |
| 快照是实例目录 | `saveSnapshot`（MAP13963，`0x1400F3950`）先经`writeInstance`得到位置，`0x1400F3B50–8F`循环写4B实例ID和8B位置 | 目录引用已保存实例，页写出不清除此位置表；真实原版多页文件仍待验证。 |
| 冷快照完整恢复 | `applySnapshot`（MAP13870，`0x1400EB780`）在`0x1400EB7B7`调用mutator虚表`+0x80`；匹配虚表`0x14011A5C8`的该槽为`destroyAllInstances`（`0x1400E30E0`），随后遍历目录读取实例 | 原版也有完整重建成本；不能把共享写入误述为任意冷定位都无需全量恢复。 |
| 销毁的撤销数据 | `destroyInstance`（MAP13925，`0x1400F1600`）在`0x1400F1696`先保存实例，`0x1400F1777`保留删除实例位置；type2撤销调用`loadDestroyedInstance` | 销毁保留恢复内容，不能套用“所有生命周期变化都清缓存”。源端指针与内部实例ID需要区分。 |
| 页缓存与磁盘 | `doGetPageForEvent`（`0x1400EBF50`）管理LoadedPage缓存、使用序号及候选淘汰；已检查的淘汰路径释放分配并erase缓存条目 | 这是内存页缓存证据，未证明原版有磁盘滚动删除或8GiB上限。 |

原版也使用磁盘，不能保证小文件或恒定容量。长期页缓存、磁盘总量、空间不足和暂停帧淘汰行为仍缺完整对照；不能把项目的 8 GiB 滚动策略直接套到原版。

## 设计取舍与共享存储

共享仓库按对象版本、资源块和保留帧引用管理生命周期，时间分段与资源所有权分离，连续游标跨段保持状态。这是参考原版已确认机制的独立实现，未链接原版数据库引擎。

提交顺序、空间保护、元数据界限、过期租约、分析维护事件与冷缓存限制见[共享历史存储](shared-history.md)。验证使用真实SDK捕获及同次raw，覆盖对象创建/销毁/ID复用、调试绘制和接触清空、随机与跨段正倒放、持有旧快照时的淘汰、取消、损坏与失败回收。完整窗口/GPU、用户远端负载和原版长期磁盘策略仍须分别验证。
