# PhysX 3.4 arbitrary profile events / 任意性能事件样例

This console producer uses the pinned official PhysX 3.4.2 SDK (`5e42a5f112351a223c19c17bb331e6c55037b8eb`) and its checked DLLs. Only the producer is compiled as Debug. It creates a real Scene with a plane and a falling box, advances eight frames, and emits application events through the public `PxPvd::zoneStart/zoneEnd` profiler callbacks. The debugger does not simulate this scene.

生产器调用 SDK 的公开 profiler callback，由 SDK 自己生成性能事件并通过 `PxDefaultPvdFileTransportCreate` 写入真实流；不自行拼接 wire，也不调用 pvd-studio 库。JSON 真值来自每次 SDK 调用前后的 Windows QPC 和实际线程 ID。它证明 SDK 3.4 输出及解析行为，不证明原版 PVD3 的 Save 容器兼容。

事件目录与曲线命令使用当前源码构建。任意精确事件的完整区间累计，与帧间隔及固定阶段曲线是不同口径。

## Reproduce / 重复验证

From the repository root, with the existing pinned SDK and checked libraries:

```powershell
./tools/profile-events/build.ps1
./tools/profile-events/verify.ps1 -SkipBuild
```

The full `profile_curves` integration target also checks the independent phase fixture at `captures/physx-3.4-profile-metrics.pvdstream` and its JSON companion; that fixture is generated by the existing `tools/physx-features/profile_metrics.cpp` producer. Its path can be overridden with `PVD_PROFILE_METRICS_CAPTURE`. It must be available when running all ignored tests.

`verify.ps1` runs the console producer with `Start-Process -WindowStyle Hidden`, writes a fresh directory under `output/profile-events-validation`, and sets `PVD_PROFILE_EVENTS_CAPTURE` while running `cargo test --locked -p pvd-core --test profile_curves -- --include-ignored`. It then builds the Debug CLI and runs the independent CLI checks below. `-GenerateOnly` generates the capture and truth without claiming a parser test passed. `-OutputDirectory` selects a destination; existing capture/truth files are rejected. No native windows, user input, original PVD process, global tools, or frozen release package are involved.

For an existing pair of capture/truth files and an already built CLI:

```powershell
./tools/profile-events/verify-cli.ps1 -Capture captures/physx-3.4-profile-events.pvdstream
```

The CLI check reads `frame` to establish the Scene generation, `profile-events` to resolve all six exact keys, `profile-csv` to compare all 12 complete span ticks against independent QPC intervals, and `profile-event-csv` to compare 48 frame rows. It verifies repeated inclusive sums, exact occurrence counts, thread/context isolation, first-start ordering, and empty values for missing, cross-boundary, and pending spans. It requires `stride_basis=reference_scene_generation_frames`, eight reference frames, eight captured frames, and stride one. A missing reference Scene generation must fail before creating a CSV; an existing output must fail without changing its SHA-256. CSV artifacts, rejection diagnostics, and `result.json` are kept in a fresh `cli-*` directory next to the capture; failures terminate verification.

CLI 运行可通过终止该进程取消，但目前没有协作式 Ctrl+C 取消处理。CSV 只创建新文件，不覆盖已有输出；写盘错误或进程中断可能留下不完整的新 CSV，需结合退出状态和诊断判断，不能把文件存在当作导出成功。The CLI has no cooperative Ctrl+C handler; process termination cancels work, and write failures or interruption may leave a partial new CSV while existing files remain protected from overwrite.

The producer sources in this workspace recreate this data; `captures/` and `output/` are local generated artifacts and are Git-ignored. A fixed local fixture is available as `captures/physx-3.4-profile-events.pvdstream` plus the same-stem `.json`.

## SDK evidence / SDK 证据

All paths below are relative to `.deps/physx-3.4`:

- `PxShared/include/pvd/PxPvd.h`: public `PxPvd` inherits `PxProfilerCallback`.
- `PxShared/src/pvd/src/PxPvdImpl.cpp`: `gSdkName` is `PhysXSDK`; non-detached `zoneStart/zoneEnd` obtain the event ID and call the SDK-owned `PxProfileZone::startEvent/stopEvent`.
- `PxShared/src/pvd/src/PxProfileEventBuffer.h`: the SDK stamps events using `shdfnd::Time::getCurrentCounterValue()`.
- `PxShared/src/foundation/src/windows/PsWindowsTime.cpp`: this counter calls `QueryPerformanceCounter`.
- `PxShared/src/pvd/src/PxProfileContextProviderImpl.h` and `PxShared/src/foundation/src/windows/PsWindowsThread.cpp`: the default event thread is `GetCurrentThreadId()`.
- `PhysX_3.4/Source/PhysX/src/buffering/ScbScenePvdClient.cpp`: Scene frame end flushes PVD profile buffers and emits the frame EndSection, letting a start cross that boundary before its later stop.

`PxProfileZone` exists in internal SDK headers, but the public `PxPvd` API does not expose its zone manager. This sample uses the public callback path into that real SDK zone and does not claim to exercise multiple custom zones. All custom events are non-detached; main and worker thread IDs are actual Windows thread IDs, not the SDK detached-event sentinel.

## Coverage / 覆盖

The zone name is exactly `PhysXSDK`; event names use the prefix `PvdStudio.Profile.`. Contexts `0x435553540001` and `0x435553540002` are independent application identities; the producer rejects either unexpectedly matching the Scene address.

| Frame | Custom events |
| --- | --- |
| 0 | Scene warmup; no custom event |
| 1 | `Sample` on main/context A has three complete occurrences, including same-key LIFO nesting. `Second` starts after the outer `Sample` but finishes before any `Sample`, proving start order differs from completion order. `Sample` also occurs on main/context B and worker/context A. |
| 2 | No custom event; absent measurements must remain absent. |
| 3 | `CrossFrame` starts and remains pending across the Scene EndSection. |
| 4 | `CrossFrame` stops; two complete main/context A `Sample` occurrences. |
| 5 | Two complete main/context A `Sample` occurrences and one complete `Pending` occurrence. |
| 6 | The same `Pending` key starts again and is deliberately left open. |
| 7 | The pending start remains open through the final Scene frame. |

There are 25 independently bounded calls, 12 complete spans, and one pending start. No stop-only case or independently registered custom zone is produced. A frame number records when the producer called the SDK; parsed association must use the captured Scene timestamps and actual event ticks, rather than stream arrival order. Frame 0 has no previous Scene EndSection and cannot provide a bounded frame interval. Cross-frame and pending events cannot be presented as complete per-frame durations.

## Truth schema / 真值结构

- `sdk`, `zone_name`, `scene`, `counter_frequency`, `main_thread`, `worker_thread`, `context_a`, `context_b` describe the run.
- `steps[]` contains `{frame, lower, upper}` around each real `simulate/fetchResults` pair; its Scene EndSection timestamp must lie inside these QPC bounds.
- `calls[]` stores the exact producer call sequence with `{sequence, kind, event, context, thread, frame, lower, upper}`. Each raw start/stop timestamp must lie within its own bounds.
- `spans[]` stores complete pairs, including `start_frame`, `end_frame`, `start_sequence`, `end_sequence`, and both QPC intervals. Pairs are recorded in completion order; same-key nesting uses LIFO.
- `pending[]` stores the unmatched start in the same shape as a `calls[]` entry.

JSON pairing is recorded independently while calling SDK methods. It does not decode the capture. IDs, timestamps, durations, byte counts, and hashes can change on regeneration.

## Verification

`verify.ps1` generates a new stream/truth pair and compares the core and CLI results against the SDK call bounds. It checks six exact event keys, 12 independently bounded spans, 48 curve rows, and the expected pending/cross-frame diagnostic states. Producer success alone does not establish decoder or CLI correctness.

Generated pointers, timings and hashes vary between runs. Use the matching JSON from the same capture; generated fixtures and logs are not part of the repository. Default tests do not execute the ignored SDK cases.
